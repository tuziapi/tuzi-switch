## 人工测试步骤

1. 打开 Codex 自定义供应商编辑页，保存一个带 API Key 的第三方供应商。
2. 检查 `~/.codex/config.toml`：
   - 当前 provider 仅保留 `env_key`；
   - 不包含 `experimental_bearer_token`；
   - 不出现明文 `sk-...`。
3. 检查 shell rc 的 `# Codex` 分组：
   - API Key 已写入对应 env_key；
   - 不再新增旧 `# >>> tuzi-switch codex env >>>` block。
4. 在 Claude / Codex / Gemini 供应商卡片上确认存在“清除配置”按钮；在 OpenCode / OpenClaw / Hermes 上确认只有“移除配置”。
5. 打开某个 app 的清除配置确认弹窗后，切换到另一个 app，再点击确认。
6. 检查实际生效对象仍是原始 app/provider，而不是当前切到的新 app。
7. 在 Claude 或 Gemini live 配置文件中，手动把某个同名 key 改成别的值，再点击“清除配置”。
8. 检查该 key 因值不匹配而被保留，未被误删；卡片中的写入状态会被清空。
9. 对未手改的 live key 再执行一次“清除配置”，确认对应 key 会被正常删除。
10. 运行相关单测，确认不再出现 Tauri window mock warning、`baseline-browser-mapping` 提示、`--localstorage-file` warning，以及故意样本带出的 `broken config` 日志。
