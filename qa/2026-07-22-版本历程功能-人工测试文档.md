# 2026-07-22 版本历程功能人工测试文档

## 测试范围

本次测试仅覆盖版本历程功能：

- 顶部入口与新版状态标记。
- 当前版本、最新版本和版本数量展示。
- 52 个正式版本记录。
- 版本展开与收起。
- 搜索、分类筛选和筛选重置。
- GitHub Release 跳转。
- 中文、英文和日文界面。
- 窄窗口、浅色和深色主题适配。
- 与现有检查更新功能的职责隔离。
- 开发预览与正式桌面应用的数据隔离。

## 测试环境

为避免影响已安装的正式应用，人工测试使用隔离开发实例：

| 项目 | 配置 |
| --- | --- |
| 产品名 | `兔子switch 开发预览` |
| Bundle ID | `com.tuziswitch.desktop.codexpreview` |
| 前端端口 | `3011` |
| 数据目录 | 临时隔离 HOME 下的 `.tuzi-switch` |

测试期间不要关闭或操作 `/Applications/兔子switch.app` 的正式进程。

## 自动化检查

### QA-A01 TypeScript 类型检查

```bash
pnpm typecheck
```

预期：退出码为 `0`，无类型错误。

### QA-A02 版本档案一致性测试

```bash
pnpm exec vitest run src/data/versionHistory.test.ts
```

预期：

- 测试文件通过。
- `2/2` 测试通过。
- 无重复版本、非法版本号、非法日期、非法 Commit 或空变更记录。
- 版本按发布日期倒序排列。

### QA-A03 前端生产构建

```bash
pnpm build:renderer
```

预期：构建成功，无版本历程相关错误。

### QA-A04 差异格式检查

```bash
git diff --check
```

预期：无尾随空格或补丁格式错误。

## 人工测试用例

### QA-01 顶部入口

步骤：

1. 打开隔离开发实例。
2. 查看主界面左上方应用名称与设置按钮区域。
3. 将鼠标悬停在时钟图标上。

预期：

- 设置按钮之后显示版本历程图标。
- 提示文本为「版本历程」。
- 按钮样式与相邻顶部按钮一致。
- 不遮挡应用名称、设置按钮或右侧工具栏。

### QA-02 打开与关闭弹窗

步骤：

1. 点击版本历程图标。
2. 分别使用右上角关闭按钮和键盘 `Esc` 关闭弹窗。

预期：

- 弹窗正常打开。
- 标题为「版本历程」。
- 两种关闭方式均有效。
- 重复打开和关闭不会出现白屏、卡顿或重复弹窗。

### QA-03 版本概览

步骤：打开版本历程弹窗，查看顶部概览。

预期：

- 显示当前安装版本。
- 显示最新正式版本 `v1.2.0`。
- 显示共收录 52 个正式版本。
- 当前版本或最新版本徽标与对应版本一致。

### QA-04 完整版本范围

步骤：滚动查看版本列表首尾。

预期：

- 第一条为 `v1.2.0`。
- 收录 `v1.0.0–v1.2.0` 和 `v3.12.4–v3.12.19`。
- 不出现 `main`。
- 每个版本均包含发布日期和至少一条变更。
- 列表按发布日期倒序排列。

### QA-05 展开与收起

步骤：

1. 展开任意三个版本。
2. 收起其中一个版本。
3. 搜索一个关键词后清空搜索。

预期：

- 多个版本可以同时展开。
- 仅被点击的版本改变展开状态。
- 搜索和清空搜索不会重置其他版本的展开状态。
- 展开内容按照变更类型分组，无空分类标题。

### QA-06 按版本号搜索

步骤：在搜索框输入 `v1.1.28`。

预期：

- 仅显示 `v1.1.28`。
- 展开后显示该版本的更新检查、重启链路和 Windows 更新清单相关缺陷修复。

### QA-07 按功能关键词搜索

步骤：依次搜索 `Codex`、`签名`、`Windows`。

预期：

- 仅显示版本号或变更正文命中的记录。
- 每个版本仅保留命中的变更条目。
- 搜索不区分英文字母大小写。

### QA-08 分类筛选

步骤：

1. 选择「缺陷修复」。
2. 再选择「安全加固」。
3. 切换回「全部类型」。

预期：

- 每次仅显示包含对应分类的版本。
- 展开后仅显示选中分类的变更。
- 切换回全部后恢复完整列表。

### QA-09 重置筛选

步骤：

1. 输入关键词。
2. 选择非「全部类型」分类。
3. 点击「重置筛选」。

预期：

- 关键词被清空。
- 分类恢复为「全部类型」。
- 完整版本列表恢复。
- 无筛选条件时不显示重置按钮。

### QA-10 无结果状态

步骤：输入不存在的关键词，例如 `no-such-release-record`。

预期：

- 显示「未找到符合条件的版本记录」。
- 不显示空白版本条目。
- 点击重置后恢复列表。

### QA-11 GitHub Release 跳转

步骤：

1. 展开存在 Release URL 的版本。
2. 点击「查看 GitHub Release」。

预期：

- 使用系统默认浏览器打开对应版本页面。
- URL 中的 Tag 与当前版本号一致。
- 应用内不渲染远程 HTML，不执行远程脚本。

### QA-12 新版状态标记

前置条件：更新检测返回高于当前安装版本的新版本。

步骤：观察顶部版本历程按钮和弹窗顶部。

预期：

- 图标右上角显示新版状态点。
- 弹窗显示可更新版本徽标。
- 点击版本历程入口不会触发下载或安装。
- 原有检查更新入口仍负责更新操作。

### QA-13 窄窗口布局

步骤：

1. 将窗口缩小至允许的最小尺寸。
2. 打开版本历程。
3. 搜索并切换分类。

预期：

- 搜索框、筛选器和重置按钮自动换行。
- 版本号、日期、徽标和变更数量不相互覆盖。
- 弹窗内容在内部滚动，不超出应用窗口。

### QA-14 深色与浅色主题

步骤：分别在浅色和深色主题下查看弹窗、徽标、筛选器与展开详情。

预期：

- 文本、边框、背景和状态标记对比度清晰。
- 无固定浅色背景导致的不可读内容。

### QA-15 国际化

步骤：分别切换中文、英文和日文后打开弹窗。

预期：

- 标题、概览、搜索占位、分类、重置、关闭及外链按钮完成切换。
- 不显示翻译键名。
- 长文本不会遮挡关闭按钮或超出弹窗。
- 版本变更正文保持中文专业描述，符合当前数据维护约定。

### QA-16 离线查看

步骤：

1. 断开网络。
2. 打开版本历程。
3. 搜索、筛选并展开多个版本。

预期：

- 全部版本档案仍可查看。
- 搜索、筛选和展开功能正常。
- 仅 GitHub Release 外链因离线不可访问，不影响弹窗其他功能。

### QA-17 正式应用隔离

步骤：

1. 保持正式应用运行。
2. 启动隔离开发预览。
3. 在开发预览中打开版本历程并执行搜索、筛选。
4. 检查正式应用仍在运行。

预期：

- 两个桌面实例可以同时运行。
- 开发预览产品名与正式应用可区分。
- 正式应用不会被单实例插件唤醒、替换或关闭。
- 开发预览数据库位于隔离临时 HOME。
- 正式应用 `~/.tuzi-switch` 数据未被开发实例修改。

### QA-18 重复操作稳定性

步骤：

1. 连续打开和关闭弹窗 20 次。
2. 连续切换分类并搜索不同关键词。
3. 展开和收起多个版本。

预期：

- UI 响应稳定。
- 无明显持续内存增长、重复监听或控制台未处理异常。
- 正式应用和开发预览均保持正常运行。

## 回归测试

完成上述测试后确认：

- 设置按钮仍能打开设置页。
- 检查更新入口仍能进入关于页。
- 顶部应用切换器与其他工具按钮正常。
- 版本历程不会触发供应商切换、代理启停或配置写入。
- 正式桌面应用未被关闭、替换或修改数据。
