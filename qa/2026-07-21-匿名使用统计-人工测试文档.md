# 2026-07-21 匿名使用统计人工测试文档

## 测试范围

本次测试仅覆盖新增的匿名使用统计功能：

- 默认开启。
- 用户可关闭和重新开启。
- 开关状态本地持久化。
- 正式版白名单事件上报。
- 开发版禁止上报。
- 敏感数据不进入请求。
- 网络异常不影响业务。

## 测试前准备

1. 确认可以登录 Umami：

   ```text
   https://umami.tu-zi.com
   ```

2. 确认查看的网站 ID：

   ```text
   853b4529-0976-4f8a-b00b-6e716f9a2f20
   ```

3. 测试正式事件时使用正式构建。`pnpm dev` 不会发送统计事件。

4. 不要为了测试创建包含真实密钥的供应商；可使用无敏感信息的测试数据。

## 自动化检查

### 1. TypeScript 类型检查

```bash
pnpm exec tsc --noEmit
```

预期：命令退出码为 `0`，无类型错误。

### 2. 后端统计安全测试

```bash
cargo test --manifest-path src-tauri/Cargo.toml commands::analytics::tests --lib
```

预期：

- 所有测试通过。
- 未知字段被拒绝。
- 自定义供应商名称被拒绝。
- 错误的事件字段组合被拒绝。
- 非法版本字符串被拒绝。
- 限频逻辑通过。

### 3. 设置兼容测试

```bash
cargo test --manifest-path src-tauri/Cargo.toml analytics_defaults_on_but_preserves_explicit_opt_out --lib
```

预期：旧配置缺字段时默认开启，显式 `false` 保持关闭。

## 人工测试用例

### QA-01 新用户默认开启

前置条件：使用不包含 `anonymousAnalyticsEnabled` 字段的设置文件。

步骤：

1. 启动应用。
2. 打开“设置 → 通用”。
3. 滚动到“隐私与改进”。

预期：

- “匿名使用统计”开关为开启状态。
- 文案明确默认开启且可以关闭。
- 文案列出不采集的敏感信息。

### QA-02 关闭并持久化

步骤：

1. 关闭“匿名使用统计”。
2. 退出设置页。
3. 检查本地设置：

   ```bash
   rg -n 'anonymousAnalyticsEnabled' ~/.tuzi-switch/settings.json
   ```

4. 完全退出应用并重新启动。
5. 再次打开匿名统计设置。

预期：

```json
"anonymousAnalyticsEnabled": false
```

重启后开关仍为关闭状态。

### QA-03 重新开启并持久化

步骤：

1. 开启“匿名使用统计”。
2. 检查本地设置。
3. 完全退出并重新启动应用。

预期：

```json
"anonymousAnalyticsEnabled": true
```

重启后开关仍为开启状态。

### QA-04 设置保存失败回滚

步骤：

1. 在隔离测试环境中临时制造设置文件不可写场景。
2. 切换匿名统计开关。

预期：

- 页面提示保存失败。
- UI 恢复到切换前的状态。
- 不出现未处理异常或白屏。

测试完成后恢复设置目录权限，不保留异常权限状态。

### QA-05 开发模式不上报

步骤：

1. 执行：

   ```bash
   pnpm dev
   ```

2. 确认匿名统计开启。
3. 执行新增供应商、切换供应商、代理启停和检查更新。
4. 查看 Umami Events。

预期：开发模式操作不会新增统计事件。

### QA-06 正式版启动事件

步骤：

1. 确认匿名统计开启。
2. 启动正式版。
3. 等待一分钟后查看 Umami Events。

预期：出现 `app_started`，数据仅包含应用版本、系统类型等匿名字段。

### QA-07 核心功能事件

在正式版依次完成：

| 操作             | 预期事件                               |
| ---------------- | -------------------------------------- |
| 应用切换 | `app_selected` |
| 供应商新增/编辑/删除/切换/排序/测试 | `provider_action`，对应 `action/result` |
| 代理启停、路由、故障转移、熔断 | `proxy_action` |
| OAuth 登录/退出 | `auth_action` |
| 配置导入/导出、备份/恢复 | `config_action` |
| WebDAV 测试/上传/下载 | `webdav_action` |
| 更新检查/下载/安装 | `update_action` |
| 目录/终端/开机启动 | `setting_action` |

预期：仅成功完成的操作产生事件；失败操作不应被统计为成功。

### QA-08 关闭后停止上报

步骤：

1. 在正式版关闭匿名统计。
2. 记录关闭时间。
3. 切换供应商、启停代理并检查更新。
4. 完全退出并重新启动应用。
5. 查看 Umami Events。

预期：关闭后不再出现新的相关事件，重启也不会出现 `app_started`。

### QA-09 高频操作限流

步骤：

1. 在正式版快速重复操作同一功能。
2. 查看网络连接和 Umami Events。

预期：

- 不产生无上限并发请求。
- 高频重复事件受到前端去重和后端限频控制。
- UI 无卡顿，内存不持续增长。

### QA-10 网络异常

步骤：

1. 临时断网或阻断 `umami.tu-zi.com`。
2. 启动应用并执行核心操作。

预期：

- 应用正常启动。
- 供应商切换、代理启停和更新界面不因统计失败而阻塞。
- 不弹出统计错误提示。
- 恢复网络后应用保持正常。

### QA-11 请求内容检查

使用代理抓包工具或服务端日志检查：

```text
https://umami.tu-zi.com/api/send
```

允许出现：

- 白名单事件名称。
- 应用类型枚举。
- 切换来源枚举。
- 应用版本。
- 操作系统类型。

禁止出现：

- API Key、Token、Cookie。
- 供应商名称和接口地址。
- 对话、请求及回复内容。
- 文件名和文件路径。
- 用户名和机器名。
- 完整错误正文及配置内容。

### QA-12 Umami 后台展示

步骤：

1. 登录 Umami。
2. 打开对应站点的 Events 页面。
3. 调整日期范围。
4. 点击事件查看属性。

预期：

- 可以查看各事件次数及趋势。
- 可以按事件区分启动、切换、代理和更新使用情况。
- 事件属性只包含允许字段。
- 页面中的统计不是 Token 使用量。

## 回归测试

- 设置页其他开关仍可正常保存。
- WebDAV 同步不改变匿名统计开关。
- 供应商新增和切换流程不受影响。
- 代理启动和停止流程不受影响。
- 更新检查及安装流程不受影响。
- Tuzi 品牌、供应商数据、更新地址和会话行为保持不变。

## 备注

- Umami 数据可能存在几秒到一分钟延迟。
- GET 请求访问 `/api/send` 返回 `405 Method Not Allowed` 属于正常现象，该接口用于接收 POST 事件。
- 若正式版前端打包或启动异常，应作为独立构建问题处理，不应以开发版统计结果替代正式版事件验证。
