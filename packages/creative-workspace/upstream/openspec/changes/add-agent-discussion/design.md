# Decisions
Use optional textChat.executionMode/linkedBoardId and message.discussion metadata; retain version 1 and validate all new fields. Queue params receive conversationLink before dispatch, not after task creation. Agent executor gets an optional injected completion callback; existing callers are unchanged. Reuse configured text transport for content/reasoning and existing queue tools for media. Only generate_image and generate_video are enabled in discussion; all parameters are explicitly selected, never spreading model-produced queue metadata. Batch limit 10 per run. Chat references task IDs, never duplicates full media. Canvas insertion checks original board identity at enqueue and flush. Closing UI does not cancel runtime. Plain text sessions and existing precise generation paths remain available.

## 2026-11-10: large discussion dialog
The existing maximize control opens a centered dialog containing both the transcript and the main composer. A stable portal host moves the same React/DOM subtree between the attached slot and dialog slot; drafts, transcript state and runtime are not duplicated. Shrink returns to the attached panel; close, backdrop and Escape return to the strip without stopping execution. Size is bounded by the embedded creative workspace, not the outer desktop window. Reuse Floating UI focus management with the composer as initial focus, and mount composer dropdown portals inside the active dialog so choosing models or parameters does not count as an outside click. No persistent fields, inference protocol changes or continuous polling are introduced.
