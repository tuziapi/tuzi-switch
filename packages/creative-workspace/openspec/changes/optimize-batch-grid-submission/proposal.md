# Change: 批量生图三列布局、完整占位与交互性能

状态：用户已于 2026-11-06 选择 B，并补充授权对过重代码进行相称重构。本地实现和验证完成，随本次提交留存；未推送或发布，结果与限制见 docs/development/2026-11-06-batch-grid-performance.md。

## Why

用户反馈批量生成仍卡顿，起初只有一个生成框、随后突然出现全部，要求横排每行三个，性能优先。

源码核实：普通批量调用 image-generation-lineage-placement，默认 column；现有横排设置仅支持整批单行。画框附近采用另一套扇形/逐框避让布局。AIInputBar 在路由、参考图等准备后逐个 insertAnchor，各占位独立挂载 React 状态控制器；完成及图片 readiness 事件会通知多个控制器。以上是待测热点，尚未复现用户的“先一个后全部”，不能当作已证实根因。

此前优化主要减少等待期间 SVG 重建和预计进度保存；20 张、6 倍 CPU 降速的首轮帧间隔 P95 未改善，不能据此声称卡顿已解决。需要把提交、等待、集中完成分开测量。

## Options

| 方案 | 优势/适用 | 缺点/风险 | 维护成本 |
| --- | --- | --- | --- |
| A：只改三列排列 | 改动较小，适合仅调整视觉 | 不解决占位显示时序、任务事件和集中落图的卡顿 | 低 |
| B：三列 + 完整占位 + 定向性能优化（建议） | 同时处理布局跳变与交互；对应本次性能优先目标 | 涉及提交/取消/重试/恢复，必须验证状态与结果对应关系 | 中；优先沿用已有批次字段和任务队列 |

## What Changes — proposed B

- 新批量按序号从左到右、每行最多 3 个；整批区域统一避让，保留参考图关联。已有画布不自动重排。移除与固定三列冲突的旧“整批横排”开关，不新增布局偏好字段，不迁移已有图片。
- 同步基础校验通过后尽早预留整个批次，显示“准备中”，让完整占位获得绘制机会，再进入可能耗时的参考图/路由准备与任务提交。若准备失败、取消或切板，清理未绑定的占位；保留已启动任务，避免重复付费提交。具体位置按提交时画板快照计算。
- 一个槽位对应一个已有 batchIndex；结果按原槽落位，乱序完成不重新排队，不触发自动跳焦。支持原有比例、失败详情、单项重试及重启恢复。尺寸未知时沿用结果尺寸预留策略，实际结果超出时验证无覆盖。
- 先记录启动/等待/集中完成各阶段，再只优化实测热点：合并同一帧的展示刷新，按任务定位相关占位，避免无关完成/readiness事件导致全批重算。复用已有局部 SVG 更新；真实任务与结果持久化仍必须可靠。
- 请求数量、模型路由、批量并发保持不变。不靠降低生成数量掩盖性能问题。
