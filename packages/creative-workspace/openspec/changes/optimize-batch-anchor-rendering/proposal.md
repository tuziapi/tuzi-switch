# Change: 批量生图的桌面占位局部刷新

2026-11-05 UC-PERF-01。用户反馈生成中拖拽/输入不顺，并明确选择「局部刷新进度，保留批量数量与现有并发」。该方案已获批准。

## Why
20 张合成任务等待期间，8 秒内占位 SVG 被整棵重建 300 次；同一进度存在画布同步与展示计时器两条刷新路径。强机器空画布尚未复现显著掉帧，不能据此声称所有卡顿来源均已定位。

## What Changes
- 相同结构的桌面占位保留 SVG 节点，进度和描述仅更新变化的属性/文字。
- 展示计时器仅推进本地进度，避免只因预计进度变化就保存整张画布；真实任务事件及生命周期修复照常持久化。
- 保留阶段变化、几何、批次数量、预览、错误详情与操作更新。
- 增加节点复用回归和 1/10/20 任务合成浏览器性能对比。

## Boundaries
不减少批量数量、不修改提交并发/请求/计费/任务持久化，不新增账户字段或数据库迁移。本轮本地修复、验证与提交；发布状态单独记录。

## 继续优化（用户 2026-11-05 授权）
在既定局部刷新范围内，单轮同步复用任务快照，预计进度数字不变时不触发 React 更新，到上限后停止该展示定时器；新重试、时长配置和媒体加载继续响应。任务匹配不再为每个候选历史任务重复分配相同 Set。无批量/并发/接口/字段变更。
