# Codex 会话保留功能复刻交接文档

## 背景

本次目标是把 `cc-switch` 中与 Codex 会话保留相关的能力复刻到 `tuzi-switch`，重点解决切换官方订阅与第三方供应商后，会话历史按 `model_provider` 分桶导致“历史看起来消失”或无法统一恢复的问题。

本次实现采用 `tuzi-switch` 现有稳定桶 `tuziswitch`，没有改成 `cc-switch` 的 `custom`。这样新写入 live 配置、历史迁移目标、Session Manager 展示保持一致。

## 本次新增能力

### 1. Codex state DB 路径解析

新增 `src-tauri/src/codex_state_db.rs`：

- 解析默认 `~/.codex/state_5.sqlite`
- 解析 Codex 桌面端常见的 `~/.codex/sqlite/state_5.sqlite`
- 支持 `config.toml` 中的 `sqlite_home`
- 支持环境变量 `CODEX_SQLITE_HOME`
- 对候选路径去重

用途：

- 历史迁移时同步更新 Codex SQLite thread 元数据
- Session Manager 读取 thread title 时补全标题

### 2. Codex 历史归桶迁移

新增 `src-tauri/src/codex_history_migration.rs`：

- 第三方旧 provider id 迁入 `tuziswitch`
- Codex provider 模板配置迁入 `tuziswitch`
- 官方 `openai` 历史可迁入统一桶 `tuziswitch`
- 迁移前自动备份 JSONL 与 SQLite
- 关闭统一历史后，可按备份账本精确恢复当时迁入的官方会话

安全策略：

- JSONL 按行流式处理
- SQLite 更新按 chunk 分批执行
- SQLite 使用事务和 `busy_timeout`
- 只按账本还原官方会话，不把所有 `tuziswitch` 会话粗暴改回 `openai`

### 3. 后端启动与设置保存接入

修改 `src-tauri/src/lib.rs`：

- 声明 `codex_history_migration` / `codex_state_db` 模块
- 启动后后台执行：
  - 第三方历史归桶迁移
  - provider 模板归桶迁移
  - 官方历史统一迁移重试
- 注册：
  - `has_codex_unify_history_backup`
  - `restore_codex_unified_history`

修改 `src-tauri/src/commands/settings.rs`：

- 保存设置时保留后端本地迁移标记，避免前端旧缓存覆盖
- 统一历史开关变化后立即重写当前 Codex live 配置
- 开启统一历史后后台迁移既有官方会话
- 关闭统一历史后清理迁移标记和迁移意愿
- 支持关闭时按备份账本恢复官方历史

### 4. Codex live 配置写入适配

修改 `src-tauri/src/codex_config.rs`：

- 开启统一历史时注入或收敛到 `[model_providers.tuziswitch]`
- 第三方切换时支持保留官方 `auth.json`
- 统一桶注入使用：
  - `name = "OpenAI"`
  - `requires_openai_auth = true`
  - `supports_websockets = true`
  - `wire_api = "responses"`
- 当前 live 已经是自定义 provider 时，会把 active `model_provider` 迁到 `tuziswitch`，保留原 provider 表里的 endpoint/env/token 配置

目的：

- 官方订阅仍走 ChatGPT 登录认证
- 新 Codex 会话写入 `tuziswitch` 桶
- 官方与第三方历史出现在同一 Codex resume history 中

### 5. 当前 Codex 供应商即时重写

修改 `src-tauri/src/services/provider/mod.rs`：

- 新增 `reapply_current_codex_live`
- 设置开关变化后立即应用到当前 Codex live 配置
- 同步更新当前 provider 的 `settings_config`，避免下次启动或切换时又从旧模板覆盖 live
- 若本地代理已接管 live，则更新 live backup，避免释放接管后恢复旧桶

### 6. 旧历史补迁与双 SQLite 覆盖

修改 `src-tauri/src/codex_history_migration.rs`：

- 新增 `migrate_codex_defined_state_history_to_unified_bucket`
- 即使旧迁移 marker 已存在，也会补迁 state DB 中仍残留的本机自定义 provider 桶
- 迁移源限定为 `tuzi-switch` 本地 Codex provider 配置中定义过的 `model_provider`
- 启动时优先执行 state DB 补迁，再执行 JSONL 扫描，避免大目录扫描拖慢用户可见结果
- SQLite 迁移前使用文件级备份，避免 SQLite backup API 在 Codex 正运行时长时间阻塞

实测覆盖：

- `~/.codex/state_5.sqlite`
- `~/.codex/sqlite/state_5.sqlite`

### 7. Session Manager 增强

修改 `src-tauri/src/session_manager/providers/codex.rs`：

- 同时扫描：
  - `sessions`
  - `archived_sessions`
- 读取 `session_index.jsonl`
- 读取候选 `state_5.sqlite` 的 thread title
- SQLite 标题查询只读取 `id,title`，避免加载大字段 `first_user_message`
- 解析 VS Code/Codex IDE 注入上下文中的真实请求作为标题

效果：

- 统一历史后的归档会话可见
- 重命名过的 Codex thread 标题可展示
- 历史列表更容易定位旧会话

### 8. 前端设置入口

新增 `src/components/settings/CodexAuthSettings.tsx`：

- 切换第三方时保留官方登录
- 统一 Codex 会话历史
- 开启时可勾选迁入既有官方会话
- 关闭时可勾选按备份恢复官方历史

## 用户侧行为

### 后续调整：Codex 应用增强默认开启

后续按产品体验要求调整两个 Codex 应用增强开关：

1. 应用启动时，“切换第三方时保留官方登录”默认开启
2. 应用启动时，“统一 Codex 会话历史”默认开启
3. Rust 结构体字段使用 `#[serde(default = "default_true")]`，避免旧 `settings.json` 缺字段反序列化时被 `bool` 默认值误补成关闭
4. 用户手动关闭后，当前运行期间刷新设置页仍保持关闭
5. 保存 `settings.json` 前会把两个字段写回 `true`，退出应用后重启恢复默认开启
6. “迁入现有官方会话历史”仍需用户在确认弹窗中手动勾选，不默认批量迁移既有官方历史

### 开启统一 Codex 会话历史

1. 设置页进入通用页签
2. 打开“统一 Codex 会话历史”
3. 可选择“同时迁入现有官方会话历史”
4. 后端立即重写当前 Codex live 配置
5. 既有官方会话与本机旧第三方 state DB 桶后台迁入 `tuziswitch`

### 关闭统一 Codex 会话历史

1. 关闭开关
2. 可选择按备份恢复迁入的官方历史
3. 后端只恢复账本记录内的官方会话
4. 开启期间新产生在 `tuziswitch` 桶的会话不会被误改回 `openai`
