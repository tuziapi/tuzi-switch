# Codex 环境变量与端点联动交接文档

## 问题描述

- Codex 新增供应商时，用户已有 `TUZI_CODEX_API_KEY` 等环境变量会被复用，存在覆盖旧 API Key 的风险。
- 表单里不能手动指定 `env_key`，用户无法按自己的命名管理多条 Codex 线路。
- `env_key` 重复时保存入口没有明确拦截，容易让多个 provider 指向同一个环境变量。
- API 请求地址选择后，下方 Codex 配置预览里的 `base_url` 没有同步变化，保存后可能与用户表单选择不一致。
- macOS/Linux/Windows 三端需要把 Codex API Key 写到真实可生效的环境变量位置，而不是只写兔子switch 数据库。

## 修复思路

- Codex 表单新增“环境变量名”输入框，允许用户自定义 `env_key`。
- `env_key` 输入只允许字母、数字、下划线，保存前再次校验格式。
- 保存前按同一 Codex 配置内的 provider 精确检查 `env_key` 重复；重复时阻止保存并提示用户。
- 兔子线路新增编号策略改为优先避开已有变量：
  - 如果已有 `TUZI_CODEX_API_KEY`，新建使用 `TUZI01_CODEX_API_KEY`。
  - 后续按 `TUZI02_CODEX_API_KEY`、`TUZI03_CODEX_API_KEY` 递增。
  - 只要求最终 `env_key` 不重复，不覆盖用户已有配置。
- API 请求地址字段变更时，实时同步下方 Codex TOML 配置预览里的 active provider `base_url`；保存时也以表单 API 请求地址为准。
- 保存 Codex API Key 时同步写入环境变量：
  - macOS：写入 `~/.zshrc`。
  - Linux：按当前 shell 选择真实 rc 文件，`zsh` 写 `~/.zshrc`，`bash` 写 `~/.bashrc`，其他写 `~/.profile`。
  - Windows：写入用户环境变量，系统“高级系统设置 > 环境变量”里可见。
- macOS/Linux 目标 rc 文件内已有 `# Codex` 或 `#Codex` 分组时，优先写入该分组下；否则写入 tuzi-switch managed block。
- 读取和查重会扫描常见 rc 文件，避免用户手写变量或历史变量漏检。

## 更新代码架构

- `src/components/providers/forms/CodexFormFields.tsx`
  - 新增环境变量名输入项。
  - 输入端过滤非法字符，减少保存时报错。
- `src/components/providers/forms/ProviderForm.tsx`
  - Codex 表单保存前增加 `env_key` 格式校验和重复校验。
  - API 请求地址变更时同步更新 Codex 配置文本。
  - 保存时强制用表单 API 请求地址覆盖 active provider `base_url`。
- `src/utils/providerConfigUtils.ts`
  - 新增/扩展 Codex TOML 配置工具，支持设置 `env_key`、检测重复 `env_key`、同步 active provider `base_url`。
- `src-tauri/src/codex_config.rs`
  - 增加跨平台环境变量写入和读取逻辑。
  - 增加 `# Codex` 分组识别与写入逻辑。
  - Linux 只写当前 shell 对应的真实 rc 文件，不因为其他文件存在 `# Codex` 就写错位置。
- `src-tauri/tests/provider_commands.rs`
  - 覆盖已有无编号 `TUZI_CODEX_API_KEY` 时新增兔子线路应生成 `TUZI01_CODEX_API_KEY`。
- `src-tauri/tests/provider_service.rs`
  - 同步 Codex 兔子线路编号预期，确保 DB 和 live 配置不串号。
- `tests/utils/providerConfigUtils.codex.test.ts`
  - 覆盖 `env_key` 同步、重复检测、API 请求地址联动。

## 风险与注意事项

- 本地 `/Applications/兔子switch.app` 仍是已安装版本；这些改动需要发布新版本后才能在安装版里验证。
- Linux 环境变量写入按当前 shell 决定目标 rc 文件，避免扫描到任意 `# Codex` 文件后误写。
- Windows 写入用户环境变量后，已有终端或已运行的 Codex 进程可能需要重启才能读取新变量。
- 删除兔子switch 供应商卡片仍只删除 DB 记录，不删除用户真实环境变量和 Codex 配置文件。
- 发布失败时可按既定回滚策略：手动回滚本次 PR 改动并将版本号回退到上一稳定版本。
