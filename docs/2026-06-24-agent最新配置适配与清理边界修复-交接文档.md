# Agent 最新配置适配与清理边界修复交接文档

## 问题描述

本轮围绕各 agent 最新配置方式与供应商配置清理，集中修复了几类问题：

- Codex 仍可能沿用旧的 `experimental_bearer_token` 路径，导致明文 Key 残留或编辑态回流。
- 供应商卡片在不同 app 下“移除配置 / 清除配置 / 删除”语义不一致，且确认弹窗在切换 app 后存在串操作风险。
- Claude / Gemini / Codex 清理配置时，边界不够精确，存在误删用户手改 live 配置或误清当前 provider 标记的风险。
- Vitest 存在既有 `@tauri-apps/api/window` mock warning，Rust 存在 `get_codex_version` unused warning。

## 修复思路

- Codex 统一按最新配置方式落盘：
  - live `config.toml` 只保留 `env_key`，不再保留 `experimental_bearer_token`；
  - 编辑态和保存 fallback 路径都会清理旧 token；
  - 旧 token 仅迁移到现有 auth/env 流程，不再回写到 live config。
- 供应商卡片动作语义收口：
  - Claude / Codex / Gemini 使用“清除配置”，保留卡片，只清真实客户端配置与卡片写入状态；
  - OpenCode / OpenClaw / Hermes 只保留“移除配置”，避免和“清除配置”重复。
- 确认弹窗绑定发起动作时的 `appId`，即使弹窗打开后切换 app，也只会作用于原始 app/provider。
- 清理 live 配置时按“值匹配”收口边界：
  - Claude / Gemini 只有当 live 中的 key 对应值仍和卡片保存值一致时才删除；
  - 如果用户手动把 live 文件改成同 key 的其他值，不会误删；
  - 当前 provider 状态分别判断本地 settings 与 DB current，只清真正匹配当前供应商 id 的那一侧。
- 测试 warning 收口：
  - Vitest 补齐 `@tauri-apps/api/window` mock；
  - Rust 的 `get_codex_version` 保留能力并加 `#[allow(dead_code)]`。

## 补充修复

本轮额外清理了 3 类测试噪音：

- `baseline-browser-mapping`
  - 根因是依赖包自身按内置数据时间戳主动 `console.warn`，升级到当时最新版本也未必消失；
  - 最终在 [tests/setupGlobals.ts](/Users/shuidiyu06/tuzi-switch/tests/setupGlobals.ts) 中仅对这条固定文案做测试环境精确过滤。
- `--localstorage-file`
  - 根因是测试初始化时读取 `globalThis.localStorage` 触发 Node 内建 webstorage getter warning；
  - 已改为直接 `Object.defineProperty` 覆写，不再先探测读取。
- `broken config`
  - 属于集成测试故意构造的失败样本；
  - 已在对应测试用例内局部静音 `console.error`，保留失败路径断言但不污染输出。
