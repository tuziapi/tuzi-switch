# API 配置生效与 Codex 供应商落盘交接文档

## 问题描述

- Claude Code 部分用户保存 API 配置后，重启 Claude 仍读取旧配置。
- Codex 新增供应商时，仅保存到兔子switch 数据库；已有当前供应商时不会在 `~/.codex/config.toml` 中登记新的 `[model_providers.*]`，也不会生成新格式 profile 文件。
- Codex live 写入曾为了历史记录稳定把目标 `model_provider` 改回旧值，导致用户原有/目标 provider 被覆盖。
- 用户本机可能已存在 Codex `[model_providers.tuzi]`；旧兔子线路预设也使用 `tuzi`/`TUZI_CODEX_API_KEY`，新增或导入时有覆盖用户原有 provider 的风险。
- 首次安装后 Codex 官方预设先写入数据库，导致已有 `~/.codex/config.toml` 不会被导入为用户供应商。
- Provider 卡片操作按钮只在悬停时出现，用户在未悬停或当前供应商禁删时容易误判为“删不了”。
- 供应商卡片“删除”语义需要统一：只删除兔子switch 管理记录，不应修改 Claude/Codex/Gemini/OpenCode/OpenClaw/Hermes 等真实客户端配置。
- 自动更新安装完成后直接触发 relaunch，旧版本可能卡在更新中，缺少明确的重启确认提示。

## 修复思路

- Claude Code live 配置统一写入新版 `~/.claude/settings.json`，不再因为旧 `~/.claude/claude.json` 存在而继续写旧文件。
- Codex 保存/更新供应商时会登记主配置：
  - 保留现有 `model_provider`、MCP、projects 等配置。
  - 追加或更新目标 `[model_providers.<route>]`。
  - 生成 `~/.codex/<供应商名>.config.toml` profile 文件。
- Codex 兔子线路使用 tuzi-switch 专属编号：
  - 官方兔子预设改为 `provider-tuzi01` / `TUZI01_CODEX_API_KEY`。
  - 新增、更新或导入旧 `tuzi` 兔子线路时，自动避开已有编号，生成 `provider-tuzi02`、`provider-tuzi03` 等。
  - 用户已有 `[model_providers.tuzi]` 原样保留，不作为 tuzi-switch 可覆盖目标。
  - 表单保存入口 `save_codex_route` 会返回后端最终归一化后的 route/env/config，前端用返回值入库，避免先写 `provider-tuzi02`、再保存 provider 时跳成 `provider-tuzi03`。
- Codex live 配置导入恢复：
  - 若检测到已有 `~/.codex/config.toml`，导入为 `codex-live-config` / `当前 Codex 配置`。
  - 导入只执行一次；已有 `codex-live-config` 后启动不重复导入。
- Codex 切换供应商时，顶层 `model_provider` 指向目标供应商，不再 stable-normalize 回旧 provider id。
- Provider 切换前重新校验存量 provider 结构，避免坏数据绕过新增/编辑校验后写入 live。
- 删除供应商卡片只删除兔子switch 管理记录，不删除用户真实客户端配置文件或 env key；只有“启用/保存/移除配置”等显式配置动作才会写 live 配置。
- Provider 卡片操作区改为常显；当前供应商删除按钮保持禁用，并提示“请先启用其他供应商”。
- Codex 预设新增默认名称改成 `供应商名-我的配置`，提交前检查供应商名称重复。
- 更新安装完成后弹出重启确认框，用户确认后才 relaunch。

## 删除动作边界

供应商列表里的“删除”是兔子switch 管理动作，不是客户端配置清理动作。后续维护时按下表区分：

| 动作/API | 影响兔子switch DB | 影响真实客户端配置 | 适用场景 |
| --- | --- | --- | --- |
| `delete_provider` / 卡片删除 | 是，删除供应商记录 | 否 | 用户不想再在兔子switch 中管理该供应商 |
| `remove_provider_from_live_config` / 移除配置 | 否，保留供应商记录 | 是，从累加模式客户端配置中移除 | 用户明确要从 OpenCode/OpenClaw/Hermes 等 live 配置移除 |
| `switch_provider` / 启用 | 是，更新当前供应商 | 是，写入当前应用 live 配置 | 用户明确切换实际生效配置 |
| 新增/编辑后保存 | 是，保存供应商记录 | Codex 会登记 route/profile；当前供应商会同步 live | 用户明确保存配置 |

注意：不要把“删除卡片”当成“清理客户端配置”。即使供应商由兔子switch 创建，删除卡片也应保留用户真实配置文件，避免误删可用线路或用户手工维护内容。

## 风险与注意事项

- 本次修复不会在新增 Codex 非当前供应商时切换顶层 `model_provider`，只登记 provider；用户仍需点击启用才切换实际 Codex 使用线路。
- `tuzi` 不再作为 tuzi-switch 管理的 Codex 兔子线路 ID；它会被视为用户已有配置保留。
- profile 文件名来自供应商显示名，重命名供应商会生成新的 profile 文件；旧 profile 不主动删除，避免误删用户手工文件。
- 删除供应商不会清理真实客户端配置或 env key；如需修改真实配置，应通过启用/保存/移除配置等显式动作完成。
- 累加模式应用已有独立“移除配置”能力；如果 UI 文案同时出现“删除”和“移除”，必须保持语义区别。
- Claude 旧 `~/.claude/claude.json` 不再作为 live 写入目标；如果用户手工依赖该文件，需要迁移到 `settings.json`。
