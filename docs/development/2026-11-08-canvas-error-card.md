# UC-CANVAS-ERR-01：画布失败卡片关闭、重试与配色

2026-11-08。用户在文本聊天性能优化期间补充截图，报告画布生成失败卡片“关闭没有反应、重试有时没有反应”，并要求优化配色。本轮按截图中的失败卡片处理。基线 `1b0fde0de4d04f71131a4012912a86ce8f2990ea`，同一 `codex/opentu-text-chat` 本地分支；保留已提交的聊天性能优化，无远程推送、PR、发布、真实凭证或付费模型调用。

## 复现与修复

真实编译页面、实际 Plait 画布/任务队列/IndexedDB，只有原生 HTTP 边界使用合成返回。修复前鼠标按下再释放重试时，有 pointerdown/mousedown/pointerup 但没有 click，合成请求数仍为 2；关闭 click 虽然到达，却抛出 `Unable to find the path for Plait node`，失败卡片仍在。

1. 原生控制器向 SVG 提供 `{...element, ...nextPatch}` 展示副本，Plait 删除需要当前节点的对象身份。关闭改为点击时按 ID 从 `board.children` 获取当前节点，再交给原有 deleteFragment；保留画布删除/历史行为，不取消或删除任务记录。React 路径同样按当前 ID 解析，已不存在的卡片不重复删除。
2. 原生按钮过去只阻止 pointerdown，mouseup 仍传播到画布，可导致选中状态重绘并在 click 前替换按钮。现在完整隔离 pointerdown/mousedown/pointerup/mouseup；点击和 Enter/Space 仍按已有动作执行。
3. 内容、位置等未变化的失败卡片复用 SVG，保留点击目标和“已复制”反馈。诊断或几何变化仍重绘，不增加轮询、计时器、请求或自动重试。
4. 卡片改为白底、灰色边框与深色正文，错误原因保留柔和红色；重试为墨绿色，关闭与复制用中性描边。深色主题使用深灰绿底、浅正文和浅绿主按钮。保留现有字段、完整错误复制和操作入口。
5. 顺手修正当前生成器入口已有的 failureDetails 可选字段类型不一致；运行时格式不变。

无新增依赖、数据库字段、配置、接口契约或迁移。失败卡片缓存仅是组件内部状态。截图中的账户/模型权限网络校验错误仍需网络或账户恢复；按钮修复不表示绕过校验或保证模型调用成功。
