# UC-TEXT-05 侧边聊天与画布主输入框关联方案（历史建议）

2026-11-08 后续用户补充 Agent、生图同步和共享协同要求，当前建议以 [UC-AGENT-CHAT-01](2026-11-08-agent-chat-canvas-proposal.md) 为准。下文不再作为待选的最新实施范围。

2026-11-08：用户要求侧边聊天关联主对话框，并希望侧栏接近 ChatGPT 风格；已确认“主对话框”指画布底部的生成输入框。此文件仅为方案，不代表已实施或已授权其中全部扩展。既有附件和隐藏旧创作对话改动保持原状。

## 已核实的现状

- 文本聊天已有独立会话、草稿、附件、流式运行时；专注和并排使用同一组件。
- 已有“引用画布选中文字”和“将回复插入画布”，尚无主输入框与文本聊天之间的双向操作。
- 主输入框已有 AI_INPUT_PREFILL_EVENT 和覆盖确认，但现有处理器会重新选择模型、设置参数、清理参考内容。不能直接把聊天回复当成完整生成配置覆盖过去。
- 旧创作助手隐藏后，画布任务和凭据引导仍保留。新关联无需恢复旧对话界面。

## 关联方式比较

| 方式 | 优势与适用场景 | 缺点、维护成本与风险 |
| --- | --- | --- |
| A 两处输入自动同步，共用上下文 | 输入一次处处可见；适合完整统一聊天/生成工作区 | 聊天草稿与生成提示词用途不同；参考图、生成类型、模型参数容易串用；须重做统一状态与任务归属，维护成本高 |
| B 明确双向操作，保留各自草稿（推荐） | 先聊天打磨提示词，再交给画布执行；适合现有桌面结构 | 多一次明确操作；需要处理覆盖取消、附件引用与目标画布变化，维护成本中等、变更范围较小 |

## B 的具体交互

1. 主输入框提供“让助手优化”：把当前提示词作为侧边聊天的待发送内容并展开当前聊天；已有聊天草稿时提供保留/替换选择。操作本身不发请求。
2. 聊天回复提供“用作提示词”：回填到当前画布主输入框，保留它的生成类型、模型、数量、尺寸和参考图。已有非空提示词时确认覆盖；取消则两边均不修改。
3. 处于专注聊天时，回填后回到画布并排，并聚焦主输入框。显示回填成功后由用户点击生成，不自动产生模型请求。
4. 首轮双向传递文字。参考图仍由主输入框管理；不把聊天 PDF、代码附件隐式转作生图参考。以后需要跨区引用图片时再扩展明确的附件选择交互。
5. 画布未就绪、用户在确认期间切换画板或目标输入发生变化时，取消本次回填并给出反馈，避免内容落到错误画板。

## 侧栏视觉与布局

- 中性浅灰/深灰背景，收紧留白和分隔线，去掉当前每条会话的双行卡片外观。
- 顶部固定收起按钮、新建对话和搜索入口；历史使用单行标题，选中行轻量高亮，操作归入“…”菜单（重命名、删除）。
- 专注聊天：左侧约240–260px会话列表，中间消息区，模型选择位于顶部。
- 画布并排：右侧聊天保持可调宽度；历史通过按钮展开浮层，不再常驻一列挤占画布。收起后保留轻量入口，恢复同一会话。
- 深浅主题、键盘焦点、Esc、长标题和窄窗口一并处理；顺手修复多附件使欢迎区顶部裁切的问题。
- 不新增账户体系或模型配置页；“ChatGPT 风格”作为视觉方向，不复制其无关功能。

## 实施约束与验收

- 复用当前文本运行时和主输入框控制，不维护两份会话副本，不用轮询或逐按键同步。
- 为回填增加明确的“仅提示词”操作语义；旧任务队列/工具栏完整回填逻辑保留。新增事件字段为可选、旧调用默认行为不变，并补齐所有调用方与测试。
- 不迁移存储结构，不清理旧会话。保留长消息虚拟化、收起时暂停UI订阅、PDF懒加载。
- 重点验证双向草稿、覆盖取消、模型/参考图/数量不被覆盖、切换画板竞争、回填零请求、实际发送一次、历史菜单及收起恢复。
- 浏览器合成验证与本机原生UI分别记录。此前付费验证额度已用完，不再发起真实模型请求。
