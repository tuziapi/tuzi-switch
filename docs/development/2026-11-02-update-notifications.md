# UC-UP-01：远程新安装包提醒与手动下载

用户要求在 opentu 集成完成后，远程有新版本时提醒用户点击下载。沿用已授权的测试 main、未签名测试安装包、公开下载页和正式仓库 Draft PR；不创建正式 Release、不合并 Draft、不修改账户 API。

## 行为与渠道

客户端启动 1 秒后检查；长时间运行每 6 小时检查一次，恢复联网/回到前台时至少间隔 15 分钟重查。全局通知覆盖助手与创作工作区，顶部更新标记和设置中的手动检查继续可用。通知包含“下载更新”和“稍后提醒”，同一版本本次会话不重复弹出，用户主动关闭后跨启动记住；新版本会重新提醒。通知不会自动安装或重启。

测试包原生层根据 isolated-profile 返回渠道、编译仓库、GITHUB_RUN_NUMBER、GITHUB_SHA 和实际目标架构。关于页面展示 test-SHA 与构建序号，不能拿沿用的 1.4.2 semver 与旧正式版 1.4.3 比较。测试渠道只读取测试仓库 codex/download-pages 的公开 release.json；必须 schemaVersion=1、acceptance、固定仓库、合法构建序号/SHA、四个平台匹配链接且 artifact 未过期。仅更大序号且不同源码提示更新；回退、同包重构建、未知架构、无 CI 身份的本地包不误报。失败显示检查失败，不声称最新，也不回退旧正式版。

点击下载重新校验清单，按原生架构打开 GitHub 对应 artifact，不自动执行文件或传账户凭证。需要 GitHub 登录、解压并手动安装 Tuzi Assistant Test。正式渠道继续既有签名 updater 与 semver Release 兜底；旧正式原生若没有新身份命令，仅当真实 app ID 精确等于 com.tuziswitch.desktop 时兼容旧流程。测试包关闭正式渠道热更新加载与检查，避免只替换旧 UI 导致 opentu 消失。

## 下载发布衔接

Acceptance installers 负责前端/Python/原生验证和四个平台安装包。新增 Publish acceptance downloads 监听 main 安装包工作流完成，只有全部成功才构建下载页；支持手动指定已成功 run。发布前核对仓库、工作流、main、提交祖先、序号不倒退，以及四个平台 artifact 的归属/大小/有效期。普通提交、其他分支、失败或仍在构建的 run 不会变成可更新版本。

Pages 使用 GitHub Actions 部署。先部署下载页及完整源码/SHA256，再将完全相同的 release.json 发布到 codex/download-pages，客户端不会比下载页更早收到通知。并发发布串行，旧 run 不覆盖新 run。发布中断不改旧更新清单，可手动重跑同 run；仍以实际工作流成功和公网 HTTP 验证为交付证据。

新增清单字段 schemaVersion/repository/runNumber/publishedAt 已覆盖生成器、网站校验、客户端独立 MIT 校验器、合成测试和发布工作流。客户端下载器不复制 AGPL 网站代码。原有 pin 文件仍作为手工构建默认，工作流用经过核实的 run ID/SHA 覆盖；不修改 package semver、不执行有 push 副作用的 version 脚本。

## 验证与限制

定向覆盖四架构下载、无点击不下载、相同/旧构建、稳定渠道隔离、旧原生兼容、失效/撤回/跨站清单、缺本地身份、超时/断网、通知去重与跨启动关闭、定时与前台节流、手动下载不重启。原生覆盖渠道身份与测试包禁用正式热更新；网站来源/有效期/统计五项回归。

旧安装包本身没有这套测试渠道提醒，用户须先从下载页手动安装本次新增功能的包，后续成功发布的新包才可自动提醒。Actions 安装包保留 30 天；过期不提供失效下载，也不暗中换旧正式版。完整签名、跨平台安装升级回退和真实供应商业务验收仍沿用既有发布门禁，不能据此认定正式上线完成。

本地验证：类型检查通过；89 文件 646 项前端回归通过；isolated-profile 原生 update_ 定向 18 项通过；下载页 5 项测试及生产构建通过，renderer 构建通过。合成浏览器在 1200 浅色、680 深色验证通知、关闭后重载不再弹、更新弹窗、准确平台下载地址、无页面错误/横向溢出；没有点击真实下载或访问账户。全仓 cargo fmt --check 存在原有无关文件格式差异，修改的 Rust 文件单独格式化。

云端安装包与公网部署尚待本轮新提交完成，不能将上述本地结果当作发布完成。
