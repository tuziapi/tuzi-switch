# UC-IMG-MENU-01：画布图片右键与原图导出

日期：2026-11-04。分支 `codex/opentu-assistant-sync`，基于 `3f610e60`；本轮本地实现、验证及提交，无推送、PR、安装包发布。账户契约 `system-token-v1` 不变，不涉及 API 仓库或生产数据。

## 批准范围和设计

用户要求画布图片右键复制、显示文件位置并检查相邻问题。方案比较后用户明确选择 B“自动保存副本并定位”。

| 选项 | 行为 | 优点 | 代价/风险 |
|---|---|---|---|
| A（未采用） | 每次定位前弹出另存为 | 用户指定位置；实现简单 | 多一步操作；重复保存由用户管理 |
| B（已批准） | 原图自动写入系统 Pictures/兔子助手，再定位文件 | 一键完成；可重复定位 | 需要副本去重、缺失重建和修改保护 |

- 五项菜单：复制图片、图片另存为、显示图片文件、预览原图、复制提示词。没有提示词时禁用该项。
- 动作绑定右键命中的图片，而非先前选择。拦截图片上的右键按下/抬起，避免画图工具误触；菜单期间方向键、Home/End、Escape 有明确行为。
- 显示文件使用原图 SHA-256 前 24 位命名，核对完整字节后复用；文件已删除则重建；用户改过文件则保留并创建后缀副本，不做自动清理。
- 复制图片通过原生 RGBA 剪贴板，可以粘贴到其他应用；GIF/WebP 动图复制首帧。另存为/定位保留原始编码字节。
- 原图优先从现有缓存读取，缺失时提示找回任务结果，不用缩略图冒充、不发起生成。远程原图读取不携带账户凭证。

## 实现与相邻修复

宿主显式暴露 `imageAction`、`copyText` 能力，独立于账户连接状态；不打开旧 opentu 全量文件 IPC。新命令 `creative_image_action` 只接受主窗口、动作、图片 Base64 和显示文件名；不接受任意路径或 URL。

原生层校验实际格式、64 MiB 字节上限、32 Mi 像素上限和解码内存限制；支持 PNG/JPEG/WebP/GIF。保存使用原生对话框，取消返回 cancelled。扩展名以实际内容为准；没有后缀时补齐但不覆盖未确认的已有文件。临时文件同步后原子替换，自动副本不覆盖，拒绝目标符号链接。

同时修复：

1. 菜单固定定位在宿主 `contain: layout paint` 下出现坐标偏移和底部裁切；统一换算宿主边界，覆盖共享菜单。
2. 右键在生图工具激活时会触发画布输入；仅图片右键阻止相关绘图事件。
3. 单张图片的画布工具栏、任务、素材、编辑器、预览下载接入原生另存为。任务/编辑器取消时不报下载成功，编辑器保留未保存内容。
4. 预览图片下载原本会走 blob 浏览器下载旁路，现在走原生图片保存并显示失败。

无新增数据库字段；桥接字段可选，旧浏览器接入保持兼容。源码与上游差异保存在 `UPSTREAM-PATCHES.patch`，新增文件列入 `UPSTREAM.json`。OpenSpec 提案为 `add-canvas-image-menu`，批准来自本轮 B 答复；环境无 openspec CLI，按格式人工核对，不声称 CLI 验证通过。

## 尚未验证与范围限制

代码与合成验证不等于三平台原生验收：当前只在 macOS 编译 Rust；系统剪贴板跨应用粘贴、真实保存对话框与 Finder/Explorer 唤起，以及 Windows/Linux 安装包仍需原生验收。本轮不声称全部问题清零或可以正式上线。

批量 ZIP、视频/音频下载及旧版桌面文件迁移不在此次图片菜单实现范围；这些导出路径仍需独立原生接入与验收。自动副本不自动删除，用户可在图片目录自行管理。未更新公网版本或安装包。
