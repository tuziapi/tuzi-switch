## 问题与修复

- 用户原截图对应的记录没有关联图片任务，错误发生在前面的文本规划；“查询任务结果”的统一提示不适用于尚未提交图片任务的情况。原始网络断开的精确原因没有足够日志确认。
- 文本请求分别提示连接失败、超时、流中断；讨论规划失败明确说明尚未提交媒体任务。
- 每轮记录可选 `discussion.submission`。只有持久化确认 `not_started`、无媒体任务、且是最近一次可恢复的侧栏请求，才允许手动重试。媒体提交前先保存 `started`；旧记录缺少标记、画布来源上下文未保存等情况仍禁止整轮重放。旧消息原错误文本保留。
- 原生错误通过与数据相同的 Channel 顺序交付；前端先读完排队的字节再抛错，避免错误抢先使缓冲回复丢失。完整终止标记后的连接错误不再抹掉完整回复，未完成流仍报错。合成测试复现了该边界，不把它认定为用户原故障的唯一原因。
- 实机另发现现有 Key 引用与本地账户绑定不匹配。通过配置界面重新选择原来的同一个 Key 并保存，重启后关联保持；没有更换账户或导出真实密钥。
