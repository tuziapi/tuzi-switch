# opentu 集成界面设计 v0.2

状态：用户已批准并开始本地预览实施，完成范围见 UC-P01。任务：UC-D02。日期：2026-11-01。

本轮以用户提供的兔子助手截图为界面基线，以当前 `TuziSidebar.tsx` / `App.tsx` 为实现基线。目标是把 opentu 接进已经实现的客户端。本文与[总体方案](opentu-unified-client-design.md)配套，替代 v0.1 的五分类导航草图；本轮不改业务代码。

2026-11-01 UC-P01.2：用户已取消独立工作流模块；执行界面仅保留项目与自由画布，其专用设置和入口一并移除。

2026-11-01 UC-D03：用户提出把创作设置移到顶部导航右侧，并复用兔子账户关联 Key；新增的入口、快速设置面板与原生绑定方案见 [账户关联设计](opentu-account-binding-design.md)。本项为独立待评审设计，不能把本文 v0.2 的批准状态视为凭证关联已获实现批准。

## 1. 设计约束

| 维度 | v0.1 的问题 | v0.2 处理 |
|---|---|---|
| 导航结构 | 将工具收进“工具管理”，与当前界面不同 | 保留十个工具直接点击进入 |
| 品牌与外壳 | 另画一套顶栏与窄侧栏 | 沿用现有品牌区、macOS 窗口区、228px 侧栏和 52px 内容标题栏 |
| 账户 | 简化成了示意列表 | 保留用户截图里的连接卡及现有已连接状态，仅扩展配置目标 |
| 创作入口 | 创作变成新的顶层产品框架 | 在账户下只加一行“opentu 创作”，内部页面放到右侧 |
| 设置 | 重新设计通用设置页 | 保留现有设置分类，追加创作设置项，复用原更新器 |

## 2. 入口位置与导航层级

```text
兔子助手                       [现有品牌与折叠按钮]

兔子账户                       [原位置与行为]
opentu 创作                    [新增一行，单入口]

工具                           [原顺序、各自直达]
  Claude Code
  Claude Desktop
  Codex
  Gemini CLI
  OpenCode
  OpenClaw
  Hermes
  Grok Build
  Pi
  MiniMax Code

工作区                         [保留源码已有入口]
  MCP / Skills / 提示词 / 会话
  授权 / 本机统计 / Agents / 统一供应商
  已有条件入口按当前工具继续展示

设置                           [原底部位置]
```

推荐单入口的原因：在现有侧栏只增加一行，不把所有创作功能挤到工具列表里。备选是增加“创作”分组并展开项目/画布/素材，优势是少一次区内切换，代价是把十个工具进一步推到滚动区域；首版不采用该备选，除非用户明确要求。

实际桌面继续使用当前可滚动的侧栏中段与固定底部设置。设计预览为便于审阅可展开完整导航；不会因为截图没显示下方工作区就删除其功能。侧栏收起为 68px 时，账户、opentu、各工具图标仍可直达，提供完整名称提示。

## 3. 画面规格

### S01 创作项目页

- 左侧完整保留当前兔子助手导航；只选中新增 opentu 行。
- 右侧标题：“opentu 创作”；标题旁齿轮进入统一设置中的创作分类。历史/任务入口显示真实任务状态。
- 内容顶部二级标签：项目、自由画布；素材与任务沿用画布内入口。标签只在 opentu 内容区域存在。
- 项目页优先呈现“新建画布”及最近项目；不添加虚构用量指标或独立账户登录卡。
- 项目条目显示真实缩略图、名称、类型与最近保存信息；没有项目时使用简洁空态和导入入口。预览中的项目仅为示例。
- 无模型配置仍能新建、编辑、导入项目；点击生成时才定位模型配置，不强制先连兔子账户。

### S02 自由画布

- opentu 选中状态不变；右侧顶部使用项目名与返回项目入口。
- 保留 opentu 原画布工具、缩放、撤销、素材、参数和生成方式；草图只演示结构，不代表缩减业务控件。
- 不新增第二条常驻宽项目侧栏。项目选择用下拉，素材和参数面板按需打开。
- 原画布 warm canvas 视觉限定在内容区；外层继续使用当前兔子助手中性色和圆角。
- 用户于 2026-11-01 确认替代交互：进入 opentu 自动向上收起助手侧栏；顶部「兔子助手 ▾」打开原导航浮层，关闭不挤压/卸载画布。切回工具恢复原侧栏宽度。移除原手动“专注模式”，不改写已保存的侧栏偏好。
- 工具侧栏始终可返回；离开后草稿、视口和运行中任务保留。保存失败时显示明确错误，不伪装已保存。

### S03（已取消）

用户明确移除独立工作流，其页面、入口、专用代码与资源均不再交付。

### S04 模型配置与账户关联

- 入口一：opentu 标题齿轮 → 当前设置页的“opentu 创作”分类。
- 入口二：原账户 Key 的“配置”菜单追加 opentu 创作目标。
- 创作模型页同时提供“从兔子账户选择 Key”和“添加第三方渠道”，不要求第三方用户连接兔子账户。
- 配置面板填写名称、渠道/Key、用途和能力对应的模型。用途为自由画布，按能力分别配置默认模型。
- 保存只写配置和绑定；不生成图片、不消耗额度、不替换工具当前供应商。
- 系统令牌继续属于原账户连接流程；界面明确区分账户连接与模型 API Key。不得为“统一账户”复制系统令牌到 opentu 原前端存储。
- 第三方渠道复用原协议与参数编辑能力；设计草图中的连接/配置按钮只展示模拟反馈，不采集真实令牌。

### S05 原账户页

- 沿用截图中的居中连接卡、兔子品牌图、系统令牌输入、获取令牌和连接操作。
- 顶栏标题、设置、历史入口保持现有结构。
- 未连接时仍可操作工具及使用自己的创作渠道；连接后仅增加 opentu 配置目标。
- 不改变已有连接、断开、轮换或公开页面范围，不重新设计账户认证流程。

### S06 原工具页与全局工作区

- 点 Claude Code、Codex 等直接进入当前原页面；原工具顺序及各自选中态保留。
- opentu 是新的 View，不是外部 CLI，不加入工具 AppId，也不出现在“将 MCP 写入哪个工具”的列表里。
- 原工作区支持矩阵继续生效；opentu 的内部提示词/素材不自动与工具提示词/Skills 合并。
- 设计草图提供工具页用于核对切换位置，具体表单以现有应用为准。

### S07 素材、任务与设置

- 素材和生成任务优先复用 opentu 现有页面，通过内容区标签到达。
- 统一设置保留原分类，只新增创作模型、存储目录、旧数据导入/备份入口；更新继续原页面。
- 旧版导入流程：选择来源 → 预览项目/媒体/冲突 → 复制到新目录 → 验证 → 打开项目。导入和清理是两个独立行为。
- 对大型素材、磁盘满、目录授权失效，提示操作后果和可恢复选项；不自动清除原 opentu 目录。

## 4. 视觉与尺寸

| 部位 | 设计值 / 规则 |
|---|---|
| 主侧栏 | 沿用 228px；折叠 68px；不为了创作重新缩窄 |
| 顶部窗口区 | macOS 沿用现有 Overlay / 拖动区域，不额外复制系统窗口按钮 |
| 页面标题栏 | 沿用 52px；现有标题、设置/历史位置 |
| 导航项 | 沿用现有约 36px 行高、图标 18px、圆角及中性选中态 |
| 字体与颜色 | 继承现有主题变量、中文字体与蓝色主按钮；不引入另一套全局字体/配色 |
| 内容间距 | 项目页 24–32px；画布模式收紧至工具栏需要的间距 |
| 创作卡片 | 继承现有圆角体系；缩略图表达真实内容，避免大量装饰性状态卡 |
| 最小窗口 | 以现有 900×600 等约束实测；内容变窄时标签换行、参数用抽屉、画布仍可操作 |
| 深色模式 | 外壳沿用宿主；创作适配主题，不直接修改全局 body/class |

## 6. 本版重点验收

1. 同截图比对：品牌区、账户位置、十工具顺序、底部设置及侧栏尺寸一致；新增仅 opentu 一行。
2. 从 opentu → 任意工具 → 账户 → opentu，主外壳保持；恢复最后项目和页面状态。
3. 新入口不修改任何工具供应商、MCP、Skills 和账户登录状态。
4. 自由画布不覆盖助手的全局快捷键和浏览器历史；生成任务不随切页中断。
5. 原账户连接页完整保留；配置创作的 Key 来源与用途明确，保存不产生生成请求。
6. 模型未配置、网络失败、存储失败、运行中离开、旧项目导入都有明确状态。
7. 画面确认与业务实现验收分别记录；当前交互稿不连接真实账户、磁盘数据或模型服务。

本版待确认的是新增入口和右侧创作画面。单客户端方案 B 及基于现有兔子助手的要求已明确，不重复选择整合方向。

检查记录：本地设计预览的导航、专注模式恢复、模型必填与第三方入口通过浏览器交互检查，代表页面在 1024 / 954 / 900 / 736 / 390 / 320 像素宽度无横向溢出；无脚本异常或图标加载失败。截图与交互稿只是设计验证，不代表集成实现。现有业务代码、凭证、工具配置及用户数据未修改。
