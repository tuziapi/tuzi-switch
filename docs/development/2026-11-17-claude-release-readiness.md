# CL-LOCAL-RC-01：11 月 17 日发布准备

用户要求全面适配，并以 2026 年 11 月 17 日可发布一个版本为目标。当前结论是**尚未达到发布条件**；日期目标不替代真实功能和安装验收。本轮继续完成可独立推进的运行时打包、全量回归和候选检查，没有发布授权、推送、PR 或远端流水线执行。

## 范围选择

| 方案 | 优势与适用范围 | 代价、维护及风险 |
|---|---|---|
| 先发布完整验收的 macOS Apple Silicon 版本（建议，待选择） | 有当前硬件、官方签名副本及真实调用证据，适合首版落地 | 首版平台及 Claude 版本受限；后续版本逐个验证；仍须全部核心流程通过 |
| 所有现有平台同步发布（待选择） | 发行范围统一 | Windows / Intel Mac 尚无实测；需要对应环境、运行时、权限和安装更新验收，无法承诺明天完成 |

Mac 先行也指正式兔子助手中的 Claude 配置能力，不能把独立 P0 调试包直接标作正式升级版。当前 `claude-local-poc` 仍强制实验 profile、独立应用标识并关闭更新；正式集成和发行通道尚未完成。

## 本轮完成

- 修复全量 Vitest 误扫描 Node 原生测试的问题：原 859 项前端测试通过，但 5 个 Node 文件被错误当作 Vitest 套件；分离后 103 个前端测试文件、859 项全部通过。
- 新增 `pnpm test:claude-local-runtime`：自动生成临时合成证书，不写系统信任、不需要真实 Key；83 项全部通过。独立 CI 文件仅定义验证，没有触发远端运行。
- 固定 Node 24.22.3 的官方 macOS ARM64 归档与 SHA-256，解包仅接受指定普通文件，拒绝链接和超大成员；4 项测试通过。许可证和来源摘要随包保留。
- 内置 `tuzi-claude-node` sidecar；打包应用只认自身运行时，缺失时拒绝就绪，不回退到用户其他工具。开发态保持原检测方式。
- 以实际内置 Node 重新跑 83 项核心 JS 测试，实际包内摘要一致；设置 `PATH=/usr/bin:/bin` 启动实验包，原生界面显示 Node 就绪。
- 原生 `local_` 22 项、默认不启用特性的 Cargo 检查、macOS arm64 Debug 打包通过。

构建命令仍为 `scripts/build-claude-local-p0.sh`，先准备校验后的 sidecar，再构建。它不会安装、发布或修改正式版。当前包的身份、摘要和检查结果见 [证据 JSON](attachments/claude-local-p0/release-readiness-2026-11-16.json)。

## 发布门槛

| 门槛 | 状态 | 放行所需证据 |
|---|---|---|
| 本地模式、主要汉化、Code 多轮及文件恢复 | 已有实机证据 | 集成最终候选后回归，不能复用旧包结论替代 |
| 普通聊天和附件 | 阻断 | 用户同意追加 CA Basic X.509 用途并亲自完成系统授权后，获得真实回复、多轮与附件结果 |
| Cowork 与电脑控制 | 未通过 | 指定临时目录读写、指定测试窗口操作、系统权限拒绝与授权、停止与恢复 |
| 语音 | 服务通过，UI 未通过 | 用户选择本地按钮或原生协议；真实麦克风输入、取消、重试与转写填入 |
| 独立副本、更新隔离 | 已有实测 | 最终包重新验证版本/签名、个人目录不变与禁更新策略 |
| 内置运行时 | 本轮通过 | 最终签名安装包中重验，干净环境首次启动 |
| 最新桌面代码组合 | 待集成 | 桌面工作区 HEAD `fa39f0f7`，与 P0 基线共同祖先 `6a7df853`，桌面侧另有 14 个提交。正式候选需保留其功能并做组合回归 |
| 正式安装、升级、回退及签名 | 未通过 | 正常应用身份、旧数据保留、运行中升级阻止、候选签名与升级/回退实测 |
| 发布安全与许可材料 | 未完成 | CONNECT/TLS 本地调用边界复核；嵌入 AGPL 核心的联合分发材料及对应源码处理明确 |
| 平台与版本范围 | 待用户选择 | 公开支持列表与实测证据一致，不声明未测平台或所有 Claude 版本兼容 |

顺序：先解决授权与语音方案 → 跑通真实用户流程 → 整合正常桌面构建 → 冻结候选 → 在同一候选上验证安装/更新/回退 → 用户验收及明确发布授权。任一核心阻断仍在，不标记“全功能已适配”或“可正式发布”。

待用户确认的三项：补充现有 CA 的 Basic X.509 信任、语音入口方案、首版平台范围。证书属于新增信任用途，不能从“明天发布”的日期要求推定授权。
