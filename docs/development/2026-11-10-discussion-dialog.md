# UC-DISCUSS-UI-03：讨论大弹窗

用户反馈贴合主输入框的展开区偏小，要求可弹出更大的窗口。本轮保留方案 B 的窄条和默认附着面板，仅将原“展开阅读”升级为居中大弹窗。只做本地开发、模拟验证和隔离体验包，无付费请求、推送或发布。

## 交互与实现

- 展开后最大 1000×820px，受创作工作区边界约束；小窗口保留 12px 边距。背景画布仍可见，关闭/缩小后继续操作。
- 讨论记录、模型选择与底部主输入框一起放大；同一 portal host 搬移原 DOM，保留草稿和同一个会话，不创建第二套输入框或运行时。
- 缩小返回原附着面板；关闭、遮罩或 Escape 返回窄条；关闭不取消后台任务。弹窗中另有明确的停止按钮。
- 复用现有 Dialog 的焦点管理，以主输入框作为初始焦点。模型、数量、参数等菜单挂在弹窗内，避免选择菜单被误判为外部点击。
- 大弹窗保持输入区展开，避免点击计划按钮时因输入框失焦收缩而移动目标。附着面板保持原有收缩规则。
- 讨论标题栏的图标不再单独命中鼠标，鼠标按下时保留输入焦点，避免原生文本选择保护或输入区收缩干扰展开/关闭按钮；键盘操作沿用原逻辑。
- 无新增持久化字段、依赖、后台轮询、推理协议或付费调用；ResizeObserver 仅用于打开的附着面板，弹窗靠 CSS 布局。

- 两种浏览器各 6 组本地 Codex 模拟流程通过，包含弹窗内切换图片/视频执行模型、独立文本模型选择、连接/断开、流式计划、从聚焦输入框点击确认生成、停止与失败不静默回退。
- 模型/参数/提示词历史的既有单元测试 54 项通过；创作构建、生产二次打包与宿主 TypeScript 检查通过。既有构建体积/Sass 弃用警告和测试环境 IndexedDB 提示保留，不冒充完整上游类型检查通过。

## UC-DISCUSS-UI-04：大弹窗内容宽度修正

用户截图反馈两侧空白过大。原因是外层已放大到 1000px，但消息列表仍继承 730px 最大宽度与居中边距。本轮仅修改大弹窗样式：消息列表铺满可用宽度、左右保留 24px；窄窗口保留 18px。普通讨论与虚拟列表共用相同内容边距，虚拟列表保留零上下内边距，不改变虚拟滚动高度计算。附着面板和独立侧栏原有宽度不变。无新增字段、监听器、后台逻辑或请求。

创作及生产页面构建通过。临时几何核查在 Chromium 浅色、WebKit 深色均实测 1000px 弹窗内回复/计划宽 950px、左右各 25px（含边框），无横向溢出；复用既有讨论回归，两浏览器各 13 组通过，含小窗、收起、草稿和模拟计划落画布。未增加低影响样式专用单元测试或发起真实模型调用。原生 Release/app 构建、ad-hoc 严格签名及 1619 文件来源重建通过。CUA 检查确认原讨论及五个完成结果恢复；实际窗口截图确认正文和计划铺满可用区域，当前停留在放大讨论。新版目录 `/Users/sdy09/Documents/tuzi-switch-artifacts/discussion-width-2026-11-10`，二进制 SHA256：`edf3895fc5a5c2376456a0581236094fa50faf6710ea335c9ed645e16aa03799`。沿用原隔离 profile。既有本地 Codex 连接是进程内状态，重启后需重新连接；本轮未发起连接或推理。见 [宽度修正验证](evidence/2026-11-10-discussion-width.json)。
