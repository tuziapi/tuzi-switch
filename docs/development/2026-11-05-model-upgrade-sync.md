## 源码核查

1. `model-config.ts` 的 `isGPTImage26ModelId` 只接受 1k；flare/sunburst 缺少对应静态配置和专门参数策略。
2. `gpt-image-26-request.ts` 为 1k 清理格式、质量等旧参数，保留 `n=1`、Base64 和原始尺寸语义。直接扩大判断范围会删除其他分组可能需要的 GIF/SVG 参数。
3. `runtime-model-discovery.ts` 已支持认证 `/v1/models`、公开元数据补充、手动模型合并和用户勾选。但没有升级修订标记；刷新快照在请求前读取，自动刷新加入后需防止迟到结果覆盖过程中修改的选择/来源。
4. `provider-model-refresh.ts` 在凭证变化时获取模型后全选；不能原样当作升级增量刷新策略。
5. `packages/creative-workspace/vite.config.ts` 仍将 `__APP_VERSION__` 写为 `1.4.2-creative-preview`，不能用于判断实际兔子助手升级。宿主当前为 1.5.5，曾存在同版本重建，必须覆盖此情形。
6. 宿主 `CreativeWorkspace.tsx` 首次进入创作才加载大包。若希望启动后自动刷新，需提供后台同步入口，避免为查模型提前挂载画布、任务执行器和快捷键监听。
7. 账户关联通过现有 native source reference 发送模型请求；原生检查 Key 权限和模型端点。公开模型广场只能补充描述与类型，不能扩张授权模型集合。

## 两种范围

两种方案都包含升级后台增量获取模型，不再要求用户去设置中手动获取。

| 范围 | 优势、适用场景 | 缺点、风险、维护成本 |
| --- | --- | --- |
| A：三个型号的基础生图、普通编辑与已有渠道的提示词 GIF | 改动较小，适合先覆盖已测试的 default/Codex 使用方式；维护成本较低 | 官方分组 GIF/SVG 还不完整，不能对外称三个型号全部能力已适配；需明确显示限制 |
| B：按来源分组接入（推荐） | 三个型号有独立分类与描述，flare/sunburst 的格式选项根据明确分组能力区分；适合当前已有多分组账户配置 | 增加能力解析、界面、请求与文件保存的回归成本；未知分组不能猜测支持，官方分组实际生成仍需独立验收 |

用户最终选择 A，以下 B 说明仅保留为未采用的评估方案。不增加圈画编辑或规划强度开关；它们仍缺少可依赖的渠道验证。新增能力策略不以模型名称、HTTP 200 或公开文案作为 Key 有权限的证明。若选 A，明确限制范围而非静默清理官方分组参数。

## 两案共用的自动同步行为

- 更新后启动兔子助手，在主界面就绪后后台检查已保存且启用的创作来源；不要求打开设置或点击获取。创作首次打开与后台同步共用同一任务，禁止重复请求。
- 使用真实宿主版本和稳定构建/模型适配修订标识。新版本和有模型适配变更的同版本重建均可触发；日常重启、切页和组件重挂载不重复成功同步。不使用每次启动的时间戳作为版本。
- 账户来源在当前连接和原生桥就绪后读取；离线/未连接不阻塞界面，连接恢复后补做。手动来源使用已经保存的 Key 和原地址，禁用/空凭证/不支持模型端点的来源跳过。首次未配置用户不自动创建来源或 Key。
- 读取认证 `/v1/models`；公开说明只补充返回的模型。自动加入本次新发现且有权限的模型，保留旧的取消勾选、手动模型、自定义绑定与仍有效的当前默认选择。
- 成功返回的授权列表不再包含的普通模型不继续标为当前授权可用；保留必要历史任务引用，不自动选一个不同价格的替代模型。手动模型继续遵守既有调用权限检查。
- 断网、超时、无效/空列表不清空旧列表，不写成功标记。有界退避重试并在恢复联网/重新连接/再次启动时补做；禁止高频轮询，保留手动重试入口。
- 请求期间更换账户、来源、Key、地址、分组，或删除/禁用配置时取消旧请求，并在提交结果前复核身份。刷新中用户改勾选或自定义模型，以提交时的最新设置合并，不能覆盖。
- 只有目录和成功标记都可靠保存后才认为完成。存储失败保留内存状态并允许下次重试；错误信息不得包含 Key、认证头或原始供应商回显。
- 本轮自动同步只读取目录，不产生图片、付费调用、账户 Key 创建/修改，也不改变已有批量数量与并发。

## B 的能力与兼容要求

- 三个精确型号分别注册为图片模型；不误识别未知的 `gpt-image-2.6-*`、不更改旧 2/2.5 型号默认参数。
- 区分型号和已知来源分组策略。优先原生关联提供的真实来源信息；手动来源信息不足时显示能力未确认，不能通过任意填写价格分组宣称服务端已支持。
- 普通生图与原图编辑复用现有 images 接口。针对提示词 GIF 渠道避免携带使其失败的格式字段；明确支持格式参数的分组按选项发送。不能仅扩大 1k 判定并统一删除参数。
- 公开声明的官方分组 GIF/SVG 请求按明确契约实现，不能凭提示词猜格式。SVG 编写模型的选择不写死“仅 gpt-5.5”，未知支持范围不做任意模型支持承诺。
- 保留实际媒体格式与字节，GIF 入画布后仍有动画；SVG 按既有安全媒体方式处理、不得注入可执行 HTML。下载、预览和缓存保持正确 MIME/扩展名。
- 参数、能力与说明须说明平台/分组范围，不承诺固定尺寸、时长、速度或价格。新增字段可选，补齐默认值、旧缓存/旧任务读写、导入导出和规范化。

## A 方案最终实现

- 三个精确型号共用基础参数适配，支持 Images 生图、multipart 普通编辑和提示词 GIF，保留实际媒体字节及尺寸；旧 2/2.5 模型和默认选择不变。模型提示明确 default/Codex 范围，官方分组专用 GIF/SVG 尚未接入。显式 `output_format=gif/svg` 返回范围说明，不静默降级成 PNG。已有 SVG 响应兼容解析保留，但不代表本次新增 SVG 生成能力。
- 模型详情来自公开文案时仍覆盖为客户端当前基础范围，旧缓存也修正图片类型与说明；手工模型和自定义绑定不覆盖。
- 启动主界面后延迟 1.5 秒加载独立 `model-sync` 入口，进入设置之前即可刷新。该入口与创作模块共享设置、模型目录和账户桥；不挂载画布或任务执行器。宿主负责桥接生命周期与清理。
- 实际宿主版本来自根 package.json；刷新修订为版本号加创作集成/模型相关源码内容 SHA-256 摘要。相同源码重复构建保持稳定，模型适配变更的同版本重建会触发。没有写入构建时间或随机修订。
- 已保存且启用的来源逐个后台获取，成功后只增加新发现的授权模型到可选集合，保留用户取消勾选、手动模型、有效当前模型。服务器删除的普通模型退出当前目录，历史任务不被重提或替换。
- 刷新提交前复核账户、来源及当前请求序号；删除、禁用、修改凭证/地址/分组或断开时废弃旧请求。合并读取提交时最新选择和手动绑定。后台等待正在进行的手动发现，新手动请求可以取代旧后台结果。
- 单来源失败使用 5 秒、30 秒、120 秒重试，之后停止本轮自动重试；联网事件、重新连接/变更来源或下次启动可再次尝试。既有目录保留，界面不被阻塞，不在错误消息中保留供应商回显或凭证。
- 目录持久化改为串行快照，并提供严格 flush 确认写入成功，避免较早的异步加密结果覆盖新设置。普通设置保存保持原失败兼容行为；自动同步仅在目录确实保存后写完成标记。补齐既有 `models-endpoint` 来源字段的规范化保留，避免重载后把认证目录误判成静态回退。

## 新字段与旧数据兼容

没有添加业务数据库字段或修改账户 `system-token-v1`。独立本机记录 `tuzi-creative-model-refresh-v1` 是以 profileId 为键的对象，字段为：

| 字段 | 类型与验证 | 缺省/用途 |
| --- | --- | --- |
| revision | string | 缺失或旧值触发刷新；实际宿主版本与源码修订 |
| source | 64 位十六进制 SHA-256 | 已保存来源参数及账户 ID 的摘要；不保存 Key、账户引用或原地址 |
| discoveredAt | finite number | 与成功保存的目录时间对应；目录丢失/替换则重新检查 |

记录损坏、为空、格式不符时按未同步处理；不进入创作配置导出或云同步。删除来源后下次成功写入清理对应旧标记。写入标记失败不记成功并保留重试机会。旧设置、旧任务无需迁移即可加载；代码回退时旧版忽略此独立记录。
