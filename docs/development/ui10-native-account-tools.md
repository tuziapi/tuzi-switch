# UI-10 账户密钥配置新工具

2026-10-27，按用户确认将兔子账户单条 Key 配置入口扩展至 Grok Build、Pi、MiniMax Code。选择工具后按模型公开协议筛选，确认配置后保存并跳转定位；已有来源可直接查看。保留原七工具的账户配置和独立原生工具适配器。

支持 Responses、Chat Completions 和 Anthropic。Grok Build 使用对应的原生 `api_backend`；其上下文长度可选。Pi 和 MiniMax Code 的 Anthropic 基础地址为 `https://api.tu-zi.com`，其他情况使用 `https://api.tu-zi.com/v1`，以匹配工具追加路径的行为。模型资格和 Key 状态在原生层重新检查，一次性 reveal 证明用于授权保存；保存不调用模型。

账户来源信息和配置哈希随工具的单步备份记录，来源元数据不含密钥；备份包含原始工具文件字节，可能包含模型 Key，保存在本地并使用私有权限。恢复及后续修改会更新或重建来源；外部修改相应配置后不再声称其仍为账户来源。账户系统令牌不进入这些备份。新工具来源分别读取，单个配置损坏仅禁用对应入口，接口整体失败不阻塞原七工具。

验证使用合成账户、合成 Key、隔离文件和本地 HTTP：前端全量 73 文件 516 项通过，类型检查及 renderer 构建通过；原生全量 1445 项通过、1 项忽略，HTTP 合成测试 4 项通过。独立 macOS 预览构建曾通过；最后增加的前端读取状态保护已通过测试和 renderer 构建，但重新打包时当前环境未找到 Cargo，故桌面预览包不包含该最后修改。浏览器预览使用内存合成数据。PATH 中未发现 `grok`、`pi`、`mcode`，未验证真实安装的 CLI、真实账户、三平台行为或用户验收。仅本地开发，未 push、PR 或发布。

设计取舍见 [ADR-016](decisions/0016-native-account-tool-sources.md)。

后续 UI-11 已修正构建 PATH 并重新打包，完成实际 CLI 与本机合成上游的分层验证；详情及剩余限制见 [UI-11记录](ui11-cli-compatibility.md)。
