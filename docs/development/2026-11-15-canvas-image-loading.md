# 画布图片加载与桌面生成卡片优化

日期：2026-11-15。范围：本地分支 `codex/canvas-loading-warm-cards`，承接用户选择的 B 方案。

## 已实施

- 桌面 SVG 图片兼容层在地址解析和解码完成前保持隐藏，避免虚拟缓存地址短暂失败时绘制蓝色破图图标；HTML 图片继续作为回退。
- 画布图片优先读取已有缩略图并立即显示，随后读取并替换为原图。缩略图不会标记画布结果为已就绪，导出和结果就绪仍等待原图加载。
- 对同一地址的原图和缩略图读取增加进程内并发合并，冷启动恢复和项目切换时的重复缓存读取会复用同一个 Promise。
- 桌面原生生成中、完成和失败卡片改为暖光黄色渐变；失败操作仍是重试已有结果、复制详情和关闭，不重新发起计费生成。
- 按用户提供的网页样式补齐生成卡片顶部信息栏、批次计数和失败卡片的状态摘要；失败卡片加入浅粉色层次、状态图标、错误详情入口和移除按钮，网页 React 与桌面原生 SVG 保持一致。
- 失败摘要保留现有错误详情面板和任务恢复语义；“重试”继续根据任务状态选择重新加载已有图片或重试失败任务，避免把恢复操作误导为新的生成请求。

## 限制

当前验证使用合成缓存和浏览器测试，尚未用用户实际图片库测量冷启动、切换项目和原图解码的具体耗时，也没有据此承诺固定的秒数提升。缩略图缺失时会继续走原有原图路径；桌面 WebKit 实机仍需在实际安装包中复验。

本轮仅本地修改、验证和提交，不 push、不开 PR、不发布。
