# ADR-018：统一客户端正式分发渠道

日期：2026-11-05。用户明确确认 `AiW520/tuzi-switch` 为测试仓库，选择将正式安装包、下载页和更新渠道统一到 `tuziapi/tuzi-switch`。

## 决定

正式渠道默认 tuziapi；测试仓库保留，CI 显式传入仓库身份，同一次构建的客户端、下载元数据、浏览器校验和更新签名必须一致。只允许这两个已知渠道，正式/测试互不兜底。沿用各自既有更新公钥与私钥 secret，不旋转、复制或打印实际私钥。所有正式集成客户端只加载与原生桥一起分发的内置 renderer，更新使用完整安装包并验证签名；旧 renderer 缓存保留但不加载。

统一流水线接管两个仓库的新版本标签，停用旧流水线，避免同标签竞争上传。手动构建默认 `publish=false`，检查前端与网页编译、四平台原生测试和安装包、七种文件摘要、来源身份及签名后提供构建产物。只有版本标签和发布开关满足条件才公开 Release 并生成真实下载清单、部署 Pages。Pages Source 不符合 GitHub Actions 时在公开前拒绝继续。网页需要公开文件的 SHA256，因此最终清单在 Release 公开后生成；单独网页重试不覆写安装包。

## 替代方案及影响

沿用测试仓库直接下载改动最少，但正式源码与版本入口仍分离，不满足用户选择。将测试公钥复制给正式版会改变原正式客户端信任链，无法证明兼容，故保留原公钥并验证密钥配对。继续旧热更新会使旧缓存 renderer 与集成创作桥版本不一致，故新正式版与测试集成版都使用完整安装更新。

保持正式 application identifier、Windows upgradeCode、账户契约、凭证及数据目录；不新增数据库字段。已安装测试渠道二进制不会自动改变更新仓库，转正式版需手动安装并保留数据。缺少正式仓库写权限、签名 secret 或 Pages 配置时保留准备分支，不以测试仓库发布冒充正式构建。

## 回退与验证边界

改动以独立 commit revert；公开标签和附件保持不可变，安装回退不清数据。合成签名测试不证明真实 secret 已配对，前端编译不证明原生安装通过，更新签名不等于开发者签名或公证。实际证据与未完成项见 ../2026-11-05-official-release.md。
