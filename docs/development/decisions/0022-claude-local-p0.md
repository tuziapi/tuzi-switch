# ADR-022：Claude 本地兼容 P0 嵌入核心并复用兔子网关

日期：2026-11-16。状态：B 方案已获用户选择；P0 本地实现，完整实机验收及发行决策待完成。

2026-11-17 扩展：用户要求全部平台适配，确认 Linux 仅提供官方支持项，确认 Windows 使用官方已注册客户端加独立 profile、严格版本校验。Mac 保留签名副本；Linux 保留官方安装路径以使用其 AppArmor 规则。平台适配不更换 B 方案的网关和凭证边界。实现、验证、维护代价及未通过项见 [跨平台记录](../2026-11-17-claude-cross-platform.md)。

## 决策

把固定版本 `claude-local` 作为可选 Rust 路径依赖嵌入。兼容核心只得到一次运行的网关令牌；真实供应商凭证由兔子既有适配器使用。入口为 `/claude-desktop-local/v1/models` 与 `/claude-desktop-local/v1/messages`，模型和供应商使用启动时的内存快照。

兼容会话不参与聚合路由、故障切换、当前供应商更新或自动重试；错误直接交给调用方。已有 Direct / Proxy 供应商字段及写入语义保留。缺少路由时，仅在克隆对象上从明确的模型环境配置生成路由；没有模型则拒绝启动，不编造供应商支持能力。

P0 通过 `claude-local-poc` 显式启用，并强制使用 `isolated-profile`。试验包有独立 bundle identifier、兔子数据目录、Claude profile、Code 目录和 CA 名称。默认构建不显示入口，不加载核心。首轮关闭所有高级能力；用户后续要求跑通全流程后，语音、电脑控制、Cowork 改为自有配置中的显式可选项，缺失和旧配置仍默认关闭。后台模式、个人会话导入/同步仍关闭。

## 实机证据带来的调整

签名 Claude 2.26454.0 会主动忽略 `CLAUDE_USER_DATA_DIR`。只检查源码中存在该变量不足以证明隔离。实际使用 `--user-data-dir` 后，空白 profile 生成运行文件，所检查的个人配置摘要未变。环境参数通过 `open --env` 显式传递。换版本需要重新验证；用户后续批准适配 5.11492.5，当前门禁固定于已验证的新版本独立副本。

实机发现原客户端自动更新器会覆盖 Applications 安装包。按用户选择增加官方签名私有副本（不重签名）、自有 `desktop-profile-3p/configLibrary` 禁更新字段、代理更新 feed 返回 204 三层隔离。普通状态轮询不复制，副本有版本和签名门禁。原生日志确认禁更新生效，原安装包与检查范围内个人配置摘要未变化。原生日志仍共享，不宣称全盘隔离。

5.11492.5 附带完整 `ion-dist.asar`，核心优先使用其网页资源；普通 Chat 实测触发 VM 且被磁盘空间检查阻断。Code 真实多轮和文件任务通过不等于新版所有能力通过。后续按用户“所有流程跑通”的要求继续实现 Cowork、语音和电脑控制；可用性以各项真实验收为准，禁止以 capability 声明虚报通过。

正常停止要求先退出 Claude。会话运行记录在启动之前写入自有目录，只含版本、阶段、供应商 ID/显示名，不含凭证。异常重启后不自动接回旧令牌，要求显式恢复。跨进程文件锁保护运行目录；代理生命周期锁保护绑定、停止和改端口；停止兼容会话仅撤销本次绑定，保留共享网关。

首次完整原生启动补充发现三处上游兼容问题：内嵌 API 模板导致页面改走线上 SPA，翻译 overrides 路径导致空值崩溃，以及 Code 安装包被整包缓冲触发客户端空闲超时。隔离严格模式固定使用本机安装版本的页面资源；翻译路径按完整 locale / overrides 处理，未知路径返回 404；官方 Code 下载使用流式转发并传播取消，仍由 Claude 原有流程校验。29 项 Node 回归覆盖这些分支，具体原生验收结果见实施记录。

Tauri 的 `prevent_exit` 无法取消 restart。因此重启必须先经过原生 `restart_app` 的检查与退出预留，前端不直接使用 process restart 权限。普通退出也先检查。P0 包禁止自动安装更新；正常构建的更新功能保留。

## 取舍与后续门槛

| 选项 | 收益 | 代价 / 当前结论 |
|---|---|---|
| 嵌入核心、复用网关（已选 B） | 复用模型映射、格式转换及消费记录；统一配置入口 | 需要维护上游兼容补丁与本地 CA；先限定平台和版本 |
| 启动完整 ClaudeMom 外部应用 | 可更快演示上游已有能力 | 两套配置、凭证与生命周期，不能直接满足集成目标 |
| 重做桌面聊天界面 | 长期边界可控 | 工作量显著增加，暂不替换已批准方案 |

上游 AGPL 标识及原许可证保留；未改变整个兔子项目的许可声明。联合分发的许可处理、CONNECT/TLS 调用边界、普通 Chat 与完整汉化、跨平台、运行时随包分发和自动更新事务仍是后续门槛。不能把 HTTP Mock、截图或编译通过写成“全功能解锁”。


## 本轮补充决策：新版 VM 与语音（进行中）

新版 Chat 必须完成 VM 安装及非空系统提示词初始化。沿用官方签名客户端，不修改其安装资源；仅在自有兼容响应中提供自行编写的最小提示词。VM 使用自有 configLibrary 的 egressProxyUrl，避免系统代理将合成本地身份送往官方服务。

VM 已能连接 loopback 兼容端口，但 SSL-only CA 无法通过原生 Basic X.509 筛选。代码已准备将显式信任动作限定到 SSL + Basic 两项，并纠正 user 域撤销逻辑。新增信任用途需用户同意和系统确认，当前尚未执行；不以关闭 TLS 验证规避。

原生语音入口要求 gateway/interactive 认证与新版票据协议。可选本地语音按钮的维护代价较小，原生入口方案涉及更多认证协议。已向用户提出选择，未擅自替代。模型下载、helper 生命周期及真实本地转写先独立实现验证。

## 正常桌面构建接入（2026-11-16，源码完成，实机待验收）

拆出 `claude-desktop-local` 功能特性，只启用核心、语音和网关；它不依赖 `isolated-profile`。P0 特性改为依赖该功能特性并继续附加实验隔离，原目录和 CA 名不变。正常应用只在自身配置目录下创建 `claude-desktop-local` 子目录及 `Tuzi Claude Local CA`，不会读取或迁移 P0 的供应商、证书或会话。旧配置缺少扩展选项时继续默认关闭，没有数据库字段迁移。

正常应用更新检查在与 Claude 启动相同的操作锁内预留更新状态，检查通过后拒绝新的兼容操作，直到安装/重启返回并显式释放。恢复记录存在或正在退出时拒绝更新。安装失败可释放预留后重试，P0 仍禁止安装更新。预留只在内存中，进程退出自动消失；会话恢复记录仍持久化。

新增正常应用资源配置和本地候选构建脚本。候选为未签名 Debug 包，脚本不会安装、启动、修改版本或发布，默认发行工作流保持不启用本功能。正常身份、正式数据保留、签名更新与回退仍需同一最终候选实测，源码和单测通过不代表发行门槛通过。

## 首版平台范围（2026-11-16，用户已确认）

首版选择 macOS Apple Silicon + Claude 5.11492.5，完整功能逐项验收通过后放行。Windows 和 Intel Mac 不纳入此次兼容功能发布范围，不因此删除兔子助手原有其他平台功能。平台选择不替代 CA 信任用途授权、语音入口方案选择及真实安装升级验收。
