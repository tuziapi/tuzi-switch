# ADR-009：兔子助手显示名称与既有安装身份兼容

## 2026-10-21 正式 Windows 发行身份核正（R01）

首次发布流水线暴露 MSI light.exe 打包失败。下文旧中文名推导只针对未覆盖的本地配置，遗漏 `scripts/tauri-release-config.cjs --desktop-product-name` 从 v1.3.1 起实际将 Windows/Linux 产品名覆盖为 `tuzi switch`。因此正式 MSI 旧身份应为 UUIDv5 DNS(`tuzi switch.exe.app.x64`) = `9462cc07-4102-53d3-9279-a97d4fe6a920`，安装目录及注册表路径由模板 `{{product_name}}` 取实际发行名称。

本次恢复模板参数化并固定真实旧 UpgradeCode，避免在默认 en-US MSI 中新增不可编码的中文目录/键名，也避免新版使用另一升级代码。保留应用内“兔子助手”和现有正式安装包英文名称。v1.4.0 标签保持原样且未发布，修正随 v1.4.1 重建；新增 Windows verbose 日志以保留打包诊断。最终是否解决打包失败以真实 Windows Actions 为准，MSI 实机升级仍不冒称已验收。

日期：2026-10-19（Asia/Shanghai）；状态：已采纳；任务 B10；基线 `TA-AC-1.5-B4` / 契约 `system-token-v1`。

用户确认四项本地修改：统一显示名称、账户兔子图标、网站令牌柔和高亮、移除工具页账户返回提示。本次不改变认证、协议或工具配置事务。

## 决策

- 面向用户的应用名称统一为“兔子助手”，包括 Tauri productName、Windows 标题、HTML 标题、界面翻译、关于页面、网站复制反馈及未来发布标题。
- 保留 `com.tuziswitch.desktop`、`tuziswitch://account/connect`、内部包名、数据/安全存储/同步键、发布仓库及下载资产名。名称变更不执行数据迁移。
- Tauri 默认 MSI UpgradeCode 由 `<productName>.exe.app.x64` 的 DNS UUIDv5 派生，直接改名会改变安装身份。固定旧名 `兔子switch.exe.app.x64` 对应 `5edba27d-f9ff-522d-89b6-5110bd7a13d0`；WiX 继续使用旧安装目录和注册表键，快捷方式及产品显示新名称。
- 开机启动新条目使用新名称；状态读取兼容旧条目且不写系统设置。用户启用时先成功建立新条目，再移除已启用的旧条目；禁用时检查两种名称。macOS AppleScript 按 bundle 文件名识别条目，旧名称句柄使用旧 bundle basename；若用户保留旧 `.app` 文件名、两个句柄相同，不误删刚启用的条目。本次测试不操作用户实际开机启动设置。
- 账户三个图标位置共用透明 PNG 组件，沿用客户端蓝青多边形兔子形象；启动器原图保留。
- 网站定位提示为卡片本身的细边和淡色背景：2 秒后去除强调状态，400ms 过渡；减少动画时取消平滑滚动和颜色过渡。程序聚焦区域不显示持续外圈，输入与按钮保留键盘焦点。
- 替代 ADR-008 的 B09“工具页提供返回入口”部分：配置后仍停留和定位工具卡片，移除整块返回提示，使用顶部兔子账户入口返回。

## 替代方案与回退

未采用全局替换所有 `tuzi-switch` 标识，因为会改变深链、配置索引及更新路径；未采用只改前端标题，因为系统和安装界面仍会显示旧名。保留 MSI 身份和注册表路径可减少升级时重复安装或失去旧安装位置的风险。

两仓代码可分别本地 revert；不清数据、不轮换令牌、不恢复旧账户 OAuth。后续发布仍需另行授权，先网站后客户端即可；旧网站/客户端仍可配对使用。Windows MSI 真实升级、Windows/Linux 开机启动及系统协议弹窗名称需要对应平台验收，本机 macOS 构建和路径单测不能替代。
