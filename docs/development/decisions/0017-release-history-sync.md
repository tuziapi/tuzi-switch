# ADR-017：版本历程按需同步公开 Release

日期：2026-10-29。用户明确授权实现自动同步，并要求不影响其他正常功能。

## 决定

版本历程先展示随包静态档案；仅打开窗口时读取按发行仓库隔离的公开记录缓存，并在缓存超过6小时后请求 GitHub Releases。源仓库复用现有 `RELEASE_REPOSITORY` 构建配置，不修改更新检测、安装或发布流程。关闭窗口取消未完成请求；网络、限流、校验或存储失败继续展示现有数据，失败后5分钟内重新打开不重复请求。

请求不携带Cookie、账户令牌、Authorization或来源URL。每页100条、至多10页、总超时12秒、响应总文本至多200万字符；完整成功后才替换缓存。只接收公开、非预发布、vX.Y.Z格式的Release，日期取published_at并按上海时区显示；不信任远端跳转地址，详情链接由发行仓库与已验证版本构造。

现有版本保留人工整理的变更分类；远程发布说明另以纯文本折叠展示，新增版本直接展示说明，不猜测分类，不执行HTML或Markdown内链接。缓存只保存版本号、公开标题、日期和正文，不进入账户数据库、工具配置、导入导出或WebDAV。

## 方案取舍与回退

沿用静态档案作为离线兜底，避免GitHub不可达阻塞窗口；独立前端fetch遵循现有HTTPS CSP与GitHub CORS，不新增原生命令或共享认证通道。暂不使用Markdown渲染依赖、不自动安装、不增加全局轮询。未来需要渲染格式时再单独确认安全链接和内容策略。

回退只需移除历程Hook接线和新增同步模块，静态档案继续可用。新增缓存键为 `tuzi-release-history-v1:<repository>`，不读写其他缓存键，无数据库迁移。Windows/Linux真实WebView联网验收仍需各平台验证。
