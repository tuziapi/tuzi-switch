# ADR-013：Codex provider 标识属于卡片配置

日期：2026-10-21；状态：用户批准、本地实现。任务 R08，B4 / system-token-v1 不变。

## 决定

用户明确要求允许不同供应商卡片使用相同 `model_provider`（例如 `custom`）。卡片仍以数据库供应商 ID 区分；TOML provider ID 不再承担跨卡片唯一性。此决定替代 R04 的全局 provider 标识冲突拒绝及未启用卡片预注册规则；R04 保留用户名称、独立凭证的要求继续有效。

- 保存路由命令只规范化草稿、准备独立凭证并返回配置，不提前写 live 或命名 profile。最终 add/update 决定是否应用；首次无当前供应商时沿用原自动应用规则。
- 新增或编辑非当前卡片只保存该卡片，不改当前 config.toml。选择卡片时按原供应商服务写入；当前卡片编辑继续立即应用。
- 生效路径应用草稿中的普通设置，并整体替换目标 provider 表及其嵌套字段；其他 provider 表不从历史快照回灌。用 TOML 结构定位和渲染目标表，兼容带引号的表头，避免遗留上一卡片字段。
- env_key 独立分配及已有绑定保持，不能因为 provider ID 相同而共用凭证索引。账户入口仍可默认生成不同 ID，但这不再是必须条件。
- 现有会话历史锚点机制保留；当目标 ID 与锚点相同时，保留新卡片 name，不再套用旧卡片 name。不同 ID 的历史锚点规范化沿用原规则。
- 保留账户保存事务、备份、外部变更冲突检查和恢复逻辑；不迁移或重写已有卡片，不清理用户的旧配置段。命名 profile 仅作为现有生效路径产物，不作为卡片身份或切换数据源。

## 替代方案与取舍

仅删除唯一性校验会让保存未启用卡片覆盖当前同名表，故拒绝。自动重命名 provider 违背用户编辑意图，亦拒绝。选择将保存和应用分离，供应商凭证仍走现有独立索引路径。

普通供应商表单的凭证准备和最终数据库保存仍是既有两阶段操作；本次不宣称新增了跨命令原子事务。账户入口继续使用已有事务。未知/无效 TOML 仍报错，不用空配置覆盖读取错误。顶层和非 provider 设置延续合并语义，未提交的删除不会清理无关全局段。

## 兼容与回退

API 无改动，无数据库迁移。旧卡片可直接切换；同名新卡片在回退到 R04/R07 后会再次受到编辑时的唯一性限制，因此回退前应导出/备份并人工处理重复卡片，不能自动改名或删除。回退使用本地提交的 revert，保留凭证和测试数据；未授权远程推送或发布。

验证见 [R08记录](../r08-codex-duplicate-provider-verification.md)。
