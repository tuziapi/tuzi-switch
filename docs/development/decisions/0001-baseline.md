# ADR-001：v1.5 开发基线与本轮已确认边界

状态：已确认的产品/协作决策登记；日期2026-10-12；基线 `TA-AC-1.5-B1`。来源为本轮用户请求及问题回答，原v1.5作为产品依据。以下不代表代码已完成或发布授权。

| 决策 | 理由 | 影响 |
|---|---|---|
| 两仓库，权威PRD/契约/任务/跨仓库进度只在tuzi-switch docs/development | 避免两套需求漂移 | API保留AGENTS、版本指针、必要迁移发布说明 |
| 当前只做文档，不业务编码、不分支/commit/push/PR/迁移/部署 | 用户明确本轮工作边界 | 本轮建立T01～T22计划，不实施；现有修改保留 |
| 浏览器授权+独立public desktop client+PKCE S256+固定tuziswitch://auth/callback | v1.5既定正式路径，不交接Cookie/系统token，不内置secret | API需兼容扩展，不覆盖旧单例；原站2FA/CSRF等保持 |
| 首次一次取得首版完整必要scope | 用户不在每个页面分批授权；研发阶段不是产品分期 | 正式交付须覆盖全部原生接口；缺scope为异常，不能反复重登掩盖 |
| 原生资料：display_name、language、accept_unset_model_ratio_model、high_concurrency_enabled、record_ip_log | 用户本轮确认范围及价格两个具体开关 | 专用白名单读/PATCH，保留网站默认/说明/限制；通知/边栏/签到/安全等网页管理 |
| AT最长30分钟、RT闲置7天、授权绝对30天 | 用户本轮接受推荐时长与上限 | family稳定起点、轮换受绝对期限约束；旧客户端TTL不变 |
| 改密/重置、禁用、删号撤销本人全部桌面连接；退出仅当前连接 | 用户明确安全事件与连接边界 | 含未消费桌面code与并发签发/刷新防护；不得自动撤销其他产品OAuth/模型Key |
| 实际部署分支dev，数据库MySQL | 用户提供事实；只确认到该粒度 | 运行SHA/版本/拓扑/迁移/容量仍未核实 |
| 本地工具与账户授权独立，保留工具配置 | v1.5产品要求及已有工具兼容 | 退出不自动停模型调用；清未保存Key/账户缓存，关联按账号隔离 |
| Coding/GACCode独立网页查询，无自动提交Key | v1.5规定的入口与产品边界 | 替换对应旧查询链接/注入行为；不并入主站账单，不增加套餐API集成 |
| 后续仅预留身份来源/业务账号/凭证版本边界 | 避免把未来SSO当首版依赖 | 不接商城/分享站、不按邮箱合并账号、不实现双中心/全局退出 |
| 编码任务授权内验证通过可本地commit，两仓库codex/分支、分别提交 | 用户指定长期流程 | push/PR/合并/部署/生产迁移另授权；已提交通常revert；双仓不是原子提交 |
| 本轮只制定并行方案 | 用户不允许自动开新聊天/并行实现 | 未启动并行执行者、未建worktree；后续按文件所有权分离工作目录 |

## 尚未形成已确认技术决策的内容

新增scope具体名字、API窄路由路径、code有效期、表名/索引/迁移结构、安全存储库、限流和清理数值、统计时区、具体压测/灰度阈值都是T01/T04/T21设计项。api-contract中的P字段是候选，不能因为写进本文档集就视为用户已批准的产品扩展。

## 后续 ADR 模板

`编号/标题、状态（提议/已采纳/废止）、日期、关联Q/T/IF/AC、背景与源码SHA、决策、备选及取舍、两端影响、兼容/安全/容量风险、迁移/部署/回退、验证方式、批准或技术决定来源、替代的ADR`。普通实现选择可自主记录采纳；产品范围变化需要用户明确确认。
