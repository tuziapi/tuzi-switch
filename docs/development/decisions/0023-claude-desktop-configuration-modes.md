# ADR-023：Claude Desktop 双入口与免证书向导

日期：2026-11-18。任务：CL-MODES-1118。状态：用户已选择，本地实现。

## 背景与授权

beta.4（8388123aa682dfe00eac8dd8d8ffe6ec2f796d20）将旧向导替换为安装检测和网关提示，丢失线路下拉、模型管理、可选功能及启动入口。用户明确要求保留 ClaudeMom 集成前的普通配置页面和旧版向导，两者可切换；随后选择“恢复旧向导，接入免证书启动流程”，重点覆盖 Windows。

## 决定

- 普通配置继续挂载原有 ProviderList 和原生供应商配置流程；不另建一份线路数据。
- 模拟客户端模式恢复旧向导布局：选择线路、准备环境、检查线路、启动。复用原模型编辑弹窗，保留线路管理和高级设置。名称按用户要求，底层运行的是已安装的 Claude Desktop，不恢复 TLS 拦截服务。
- 首次默认显示向导；模式偏好以 `claude-desktop-configuration-mode` 保存为 normal/guided，异常值回到 guided，存储不可用不影响本次切换。该字段仅是界面偏好，不保存凭证，不触发线路切换、启动或配置写入。
- `prepare_connection` 和 `launch` 由原生层检查当前线路、模型配置、已安装客户端、进程退出状态及旧会话恢复标记。需要模型映射时启动现有本地路由，使用现有原子写入及回滚逻辑应用官方网关配置。启动不复制客户端、不生成或信任根证书、不关闭 TLS 校验，不自动终止 Claude。
- 保持原有 provider 操作锁以及更新/退出操作锁；启动前重新校验当前线路，防止等待路由启动期间线路切换造成误配置。复用 Windows 官方安装路径解析和 MSIX 别名回退。
- `desktopRunning` 新字段为可空布尔值；未知时前端阻止向导启动，并保留重新检测入口。前端“已发送启动请求”不等同于客户端对话成功。
- 语音、电脑控制、Cowork 保留展示并注明限制；免证书流程没有实现这些旧注入开关，因此不发送旧功能启用命令。Claude 自身支持的功能在其客户端中管理，不把置灰开关当作功能已实现的证明。
- 原有旧会话恢复和证书清理保留于高级设置；有恢复标记时，两种界面都不显示可操作的线路列表或启动按钮。

## 替代与回退

原样恢复旧兼容服务能保留其注入行为，但重新引入根证书及固定客户端版本维护，与用户选择冲突，故不采用。回退本次改动可返回 beta.4 网关页面；无需迁移或删除供应商、原客户端数据或旧会话恢复标记。

## 验证

- 50 项前端定向测试通过：ClaudeLocalPanel 21、ProviderList 7、ClaudeDesktopCatalog 20、claudeLocalRestart 2；类型检查通过。
- `pnpm build:renderer`（先构建创作工作区，再构建主应用）通过。直接运行 Vite 的首轮缺少创作工作区产物，按完整仓库脚本重建后通过。
- 原生带 `claude-desktop-local,opentu-preview` 的宿主编译通过；`claude_` 100 项测试中 99 项通过。唯一失败为既有 Claude Code 接管测试绑定固定 15721 端口，当前用户的 OpenTu 进程已占用该端口；串行复跑同样失败，未停止用户进程或改写无关测试。此次新增的动作分发、启动环境变量清理、路由需求测试均通过。
- 浏览器合成预览验证了两种模式切换、刷新记忆、线路保留、功能限制说明、启动反馈及运行后禁用再次启动。合成预览不代表 Windows 原生启动或真实模型联调。
- `scripts/check-preview-gateway.py` 通过，旧 TLS 代理脚本和证书生成脚本未恢复。
- 未进行 Windows 实机启动/对话、未发布新包；当前公开 beta.4 不包含本次修改。
