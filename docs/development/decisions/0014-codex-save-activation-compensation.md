# ADR-014：Codex 保存及启用的失败补偿

日期：2026-10-21；任务 R09；状态：用户批准、本地实施。B4 / system-token-v1 不变。

## 问题与授权

R08 后上线审查实际复现：profile 写入失败，live 保留 A，但本地设置和数据库当前标记已变成 B。普通表单还会在最终保存前写入 Key，当前卡片编辑先写数据库、再写 live，后续失败会留下部分更新。用户授权修复、提交、推送客户端分支并创建目标 main 的 PR；不包含合并、Release 或部署。

## 决定

1. `save_codex_route` 改为无写入的草稿准备命令，保留参数兼容但不使用 apiKey 写文件或迁移凭证。普通表单将 Key 仅随最终 add/update 的原生请求发送；原生在已有 env_key 规范化后写入凭证，入库前移除该临时 OPENAI_API_KEY。官方登录配置沿用原规则。
2. Codex 普通 add/update、普通启用和经 ProviderService 发起的代理热切换，在供应商操作锁内执行补偿事务。账户入口已有事务时复用外层日志，不新建嵌套日志或重复备份。
3. 复用既有配置写集和逐写入检查：settings.json、Codex config/auth/catalog/profile、独立 Key 文件及 shell 文件等，在修改之前形成私有备份。回滚前检查实际文件/权限仍匹配本操作写入，拒绝覆盖外部修改。
4. 数据库仅备份 Codex 的 providers、provider_endpoints、tuzi_provider_sources 和 proxy_live_backup 行；不复制庞大的使用日志/会话数据库。恢复现有 providers 使用更新，避免 DELETE 引起 provider_health 级联丢失；无关应用和全局设置表不恢复。
5. 失败时恢复文件、原生设置缓存、相关数据库行和当前标记；Windows 环境写入还记录注册表/进程的修改前值及尝试值，恢复前核对是否出现第三方值。代理历史锚点写入在已有事务线程执行，避免 spawn_blocking 绕过线程本地写入日志。
6. 成功或完全恢复后删除本操作新建的临时备份；外部冲突、补偿失败、异常中断保留 `codex-operation-backups/<UUID>` 的私有备份并明确报错。Unix 使用目录0700/文件0600，Windows 复用现有当前用户 ACL。此目录独立于账户保存的 tool-backups。

## 边界与替代方案

仅把当前标记移到最后无法解决 Key、数据库、profile 已部分更新的问题，故不采用。直接恢复整个数据库会覆盖用量、其他工具及并发状态，故限定 Codex 数据；普通切换也不应复制大体积日志库。

这是受检查的失败补偿，不是文件系统与 SQLite 间的硬件原子提交。进程强制退出、掉电或恢复本身遇到 I/O 故障仍可能需要人工恢复；本轮不增加开机自动重放，也不把新目录伪装成账户恢复 API 可直接消费的完整数据库。保留的 before.db 是 Codex 局部数据，不能用它直接覆盖整个应用数据库。代理服务内部的自动故障转移不是本次新增事务入口。

不改重复 provider 的 R08 行为，不改 Key 搜索清空、不改 API。涉及原生 IPC 行为的前端与后端必须一起发布，不能仅更新一侧。

## 验证与回退

见 [R09验证](../r09-codex-transaction-verification.md)。新增逐写入点故障、数据库错误、代理备份错误、外部编辑及补偿失败测试，并保留 R08 原始复现的回归。回退提交时前后端一起回退；无 schema 迁移，已有卡片不重写、不清理凭证。保留未完成操作的备份，不能自动删除。
