# ADR-026：兔子官方 MCP 一键配置与 Codex 授权

日期：2026-11-23。用户已选择“一键配置＋首次授权”，首版 Codex；本轮授权本地实现与验证，无推送或发布。

账户基线仍是 `system-token-v1`。MCP 使用 API 仓库已有的独立 OAuth 资源与审批体系；不恢复历史 `/api/desktop` 或账户 OAuth。

## 决策

- 在现有 MCP 管理页增加官方卡片，固定服务器 ID `tuzi-official` 和 `https://api.tu-zi.com/mcp`；复用现有文件与数据库事务，仅启用 Codex。
- 由已安装 Codex 的 app-server 执行 MCP OAuth 登录，打开经过同源/固定路径/资源校验的系统浏览器授权页。Codex 自己保存和刷新凭证，助手不读取凭证文件，不复制账户系统令牌。
- 原生操作异步执行，界面轮询本地状态；单操作互斥、可取消、等待有界。任何错误只返回允许的错误码，不输出原始异常或授权 URL。
- 校验配置目录一致性；独立预览沿用独立配置目录。已有同名配置或文件被修改时拒绝覆盖，保留原工具配置及数据库事务回滚。
- 验证使用临时、只读 Codex 会话，只调用 `get_account` 和 `get_overview`，不创建模型 turn。读取实际生效配置后显式关闭其他 MCP，避免检测时启动第三方进程。
- 状态区分“尚未配置”“已配置，待验证授权”“正在授权”“已连接”。连接成功保留本次查询账号与检查时间；助手账号与 MCP 账号不同则提示不一致。重启助手后必须再次检查，不持久化假定成功。
- 撤销通过固定官方连接管理页完成；打开页面不等于已经撤销。取消等待也不保证撤销了客户已在网页批准的授权。

## 取舍

| 方案 | 优势 | 代价 / 风险 | 结论 |
|---|---|---|---|
| 将系统令牌写入 MCP Header | 表面操作少 | 当前 MCP 不接受；分发长期账户管理凭证，缺少独立权限边界 | 不采用 |
| Codex 自己授权 | 复用已有安全体系，助手不保存第二套凭证 | 首次浏览器确认；依赖 Codex app-server 能力 | 已选择 |
| 系统令牌换取 MCP 专用凭证 | 可进一步减少登录步骤 | 服务端新增交换、scope、审计及撤销契约，维护两套凭证生命周期 | 后续另行评估 |

不修改 Codex 的 OAuth 凭证存储策略。测试夹具显式用临时文件存储以避免访问钥匙串；产品遵循客户已有 Codex 设置。

## 依赖与回退

先发布服务端原生客户端动态注册能力，再交付助手。多机须全部升级，现有 MCP 持久密钥与配置保持一致。没有新表、字段、索引、环境变量或客户端 schema 版本。

回退助手代码后，已配置的 MCP 仍可由 Codex/普通 MCP 管理使用；如需撤销，客户在网站撤销对应连接。不要删除账户数据或轮换共享系统令牌。具体证据见 [实施与验收](../2026-11-23-official-mcp-one-click.md)。
