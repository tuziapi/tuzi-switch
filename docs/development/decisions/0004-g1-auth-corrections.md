# ADR-004：G1 授权账户绑定与可恢复刷新

2026-10-13；技术冻结，实施和验证中。B3 / desktop-v1.1 安全修订 r1，scope desktop-v1、产品范围、30m/7d/30d 寿命及数据库版本不变。适用于 T02/T03/T06/T07；修正用户指出的四项缺陷，不表示此前检查覆盖了这些路径。

## 授权解析与账户绑定

专用授权限流与控制器必须以同一 JSON 请求内容识别桌面 client，不得依赖可由调用者伪造的 Content-Type 来跳过限流；有界解析失败必须拒绝，不得退化为旧客户端。旧 OAuth 接入方行为保持。

桌面 context.request 增加 context_token：服务端 HMAC 签名，绑定所展示账户 ID、完整授权请求和 600 秒截止。批准和取消均须校验签名、期限、请求绑定及当前纯网站 session 用户；缺失、篡改、过期或切号返回 HTTP 409 authorization_context_changed，不能签发连接或授权码。网页清除旧上下文并重新获取，显示新账户后要求再次明确点击，不自动提交。旧 confidential OAuth 不要求此字段。选择签名上下文而不是仅前端 account_id 断言，使展示账户及请求来自服务器可信快照；签名常量时间比较，不记录 context_token。复用既有 SESSION_SECRET 并作签名用途隔离；多实例须使用相同受控共享密钥，不能依赖每进程随机默认值。发布前验证密钥配置与代理结果头处理，本轮不访问线上配置。

## 明确未消费与不确定结果

桌面刷新请求只有在服务端消费 RT 之前明确拒绝的 429/503，才返回 `OAuth-Refresh-Outcome: not-consumed`，错误体为完整 OAuth `temporarily_unavailable`。本修订只在 preflight 产生该标记；事务/提交错误及未知结果不得标记。代理不得自行附加该标记。

原生仅对受信固定认证端点的刷新响应、精确状态和标记、完整有效错误体共同成立时，保留旧 RT，持久清除 in-flight journal 并保存重试截止，再进入可恢复离线状态；遵循 Retry-After、有限自动重试预算和可见性控制。安全存储失败继续 fail closed，无明文降级。服务重启后仍遵循已保存截止。裸 429/503、超时、丢失/截断响应和其他未知结果不能证明 RT 未消费，仍不得重放旧 RT。此选择保留一次轮换语义，不引入重放宽限或修改授权寿命。

## 网站连接状态

active 连接还须具有当前未旋转、未撤销且未过期的 RT；now 达到 RT expires_at（含 7 天闲置裁剪）或绝对截止即显示 expired。历史 rotated RT 不参与当前有效性判断；revoked 优先，pending 保留原 600 秒规则。列表不返回 RT/hash，不通过查询延长寿命。

## 兼容、回退与验证

这是尚未发布 G1 的安全修订，不改变 `/api/desktop` DTO/版本协商。网页和 API 必须配对升级：旧网页缺 context_token 将被拒绝，重新加载新版恢复；旧 native 遇暂时拒绝仍可能要求重连，新 native 对旧服务端无标记响应保守处理。无迁移，无凭证转换。不回退至本次缺陷实现；应用回退仍须满足 ADR-003 的撤销/清理基线。

验证矩阵：不同 Content-Type 的真实路由限流；展示 A 后 session 切 B、篡改/过期/取消、原账户正常批准及旧 OAuth；429/503 确认未消费后退避恢复、无标记/丢响应不重放、安全存储失败与重启截止；当前 RT 闲置/绝对/边界、历史轮换、pending/revoked 列表。作者测试后固定提交非作者审查，实际结果另记 g1-verification，不能以此设计宣称通过。
