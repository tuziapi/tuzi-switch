# ADR-024：免证书网关的内部路由编号与真实模型名称

日期：2026-11-19。任务：CL-GATEWAY-ROUTES-1119。状态：用户已选择 A，Mac 本地真实验证通过，未发布。

## 背景与批准

公开 beta.5 的隔离配置与启动目录不一致，修复并实机安装后，官方 Claude 5.11492.5 明确过滤 `claude-gpt-*`、`claude-codex-*` 模型，全部 11 条“兔子coding”路由不可选。宿主原先只检查 `claude-` 前缀，不足以代表客户端实际接受。

用户在比较 A（保留 GPT 等，内部编号加真实显示名）与 B（仅 Claude 模型）后明确选择 A。仅本地验证兼容性；不将内部编号描述为官方支持 GPT，也不把启动成功当作对话成功。

## 决定

- 只在本地网关输出层生成内部编号，不迁移或覆盖数据库里已有的模型映射。普通直连与旧兼容服务目录输出保持原语义。
- 内部编号由去掉 1M 后缀的原路由 ID 的 SHA256 确定，摘要逐字节转换为三位十进制数，前缀为 `claude-tuzi-route-`。编号不含模型家族名称，保持完整摘要，不依赖目录排序、显示名、凭证或进程随机值。
- Claude 配置的 `inferenceModels` 使用对象形式：`name` 为内部编号，`labelOverride` 为真实上游模型名，`supports1m` 沿用明确配置。已有自定义显示名与真实名称不同时，两者一并显示。不得把 GPT 标为 Sonnet/Opus 或伪报模型能力。
- 网关 `/claude-desktop/v1/models` 与静态配置使用同一编号和显示名；消息转发只接受已配置内部编号或历史路由 ID，并映射回实际模型。未知编号报错，不用默认模型兜底。
- 保留已有 1M 后缀处理，不新增上下文能力；旧会话路由继续识别。内部编号为传输标识，不是凭证，不影响既有网关鉴权。
- 延续 ADR-023：不改官方应用、不引入证书、不关闭 TLS、不恢复注入服务。隔离启动路径修复另行保留。

## 比较与回退

原方案直接将真实 GPT 名称加 `claude-` 前缀，容易理解但已被实机拒绝。内部编号方案保留原功能及真实模型可辨识性，代价是依赖客户端接受自定义路由；后续客户端升级仍需回归。限制为 Claude 模型维护较低，但减少用户既有功能，未被选择。

回退输出层即可恢复旧路由；无需回滚数据库或删除会话。编号方案创建的新会话在回退旧代码后可能无法继续，需要用户重新选择模型。必须分别记录本机 UI、真实请求、多轮与重启结果，Windows 实机及发行包结果独立验收。

## 验证结果

20 项原生定向测试通过；本地候选实机确认 11 模型显示、Code 与 Cowork 真实多轮、文件任务和两端冷启动续聊通过。完整版本、摘要、探针失败过程及剩余门槛见 [真实验收](../2026-11-19-gateway-route-acceptance.md)。
