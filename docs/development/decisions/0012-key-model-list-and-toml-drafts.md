# ADR-012：按 Key 获取模型与保留 TOML 编辑草稿

日期：2026-10-21；任务 R02；用户授权客户端本地修复、构建与测试，API 不修改。

配置到工具原先使用价格目录的首批100条再做工具筛选，导致 Codex 模型缺失。改为原生内部 `/account/keys/:id/models` 操作：用账户系统令牌读取本人 Key 详情及明文，再只用模型 Key 请求固定主站 `/v1/models`。这是客户端内部 IPC 路径，不是新增 API 站路由。返回前端仅模型 ID/协议元数据，不返回模型 Key。沿用现有禁止重定向、代际校验和取消机制；列表不生成或消费保存来源凭据。模型响应限制8MiB并去重，异常拒绝继续。

工具兼容性按协议元数据判断，不按模型名称白名单。未知协议显示不可选择的说明；不兼容协议隐藏。价格目录继续用于原有价格页面。保存资格检查重新读取同一 Key 的模型列表并检查状态、到期、余额、模型限制与协议。组可用性由已有 `/v1/models` 按实际模型 Key 判定，避免客户端猜测 default/auto 分组。放弃继续翻价格目录全部页的方案，因为其语义不是实际 Key 的模型权限。

TOML 原文是编辑草稿，逐字输入不触发反向序列化或自动补 provider。结构化字段只在合法 TOML 时读取更新；显式操作字段才改对应配置。CodeMirror 使用最新回调，外部值同步不再回传 onChange，按最小差异更新以保留光标/撤销体验。保留既有受管 env/wire_api 保存规则。

保存前前端与原生拒绝语法错误、缺 name 的 provider、model_provider 指向不存在配置；前端同时检查模型与 base_url。合并后的实际配置在写 shell env 和文件前再次验证。显式 `[model_providers]` 父表是合法 TOML，不当成错误；不自动删除用户历史残缺段。旧配置需先备份、检查后手动修复。

兼容与回退：服务端和 system-token-v1 契约均不变，无迁移、部署顺序或服务端回滚要求。客户端回退本修复提交；保留用户数据和旧安装包。账户本地文件现在同样遵守已有 CC_SWITCH_TEST_HOME 测试隔离目录，无该变量时存储路径不变。

## R03 用户实际验收纠正（2026-10-21）

用户截图证实 R02 Codex 仍仅显示三个5.6模型，而同 Key 手动获取列表有28项。两个入口均调用 `/v1/models`，差异是配置入口额外把协议标签当成硬门槛。此前合成模型均带 openai-response，未覆盖该实际情况。

本段覆盖上文对 Codex 的协议过滤决定：Codex 与手动“获取模型列表”一致，显示并允许选择当前 Key 返回的全部模型，不以 supported_endpoint_types 过滤或标成未知禁用。保存重新核验 Key 状态、额度、到期、模型限制及列表成员资格，不用协议元数据阻止 Codex 保存。调用协议仍由 Codex 适配器选择和校验；列表存在不等于实际模型调用成功。其余工具保留原协议筛选，原生资格方法接收已解析的目标 AppType 对应名称，避免影响其他工具。

不新增模型名白名单、不猜测模型族、不修改 API；图片模型如存在于手动列表，也会原样展示。实际是否适合 Codex 由用户选择及后续模型调用验证，本轮不发起付费测试。

## R06 已知模型列表标签与展示（2026-10-21）

用户授权简化数量提示、隐藏未知项并修正有证据的协议遗漏，暂缓后四位搜索清空问题。`/v1/models` 的DTO只有协议标签而没有端点详情；既有已验证的 `claude code` 和 `gemini generateContent` 在此响应下按已知协议别名处理。共享JSON同时供前端与Rust保存校验使用；明确冲突的路径/方法仍拒绝，未知标签不猜测、不展示禁用项。Codex沿用R03完整列表规则。计数显示读取总数，空态区分无可用模型、无搜索匹配与请求失败。读取器已有共用实现，本轮保留各入口地址语义，不改API。证据及验证见 [R06记录](../r06-model-picker-verification.md)。
