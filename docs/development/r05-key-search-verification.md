# R05 密钥搜索交互修复（2026-10-21）

任务范围：用户反馈搜索输入/状态筛选跳动、输入过程报错和后4位搜索无效。仅修改客户端，分支 `codex/tuzi-assistant-system-token`，基线 B4 / system-token-v1 不变。API 保持 `2e72a8b8786f917ee7ce1bc2dde0ce0ba2dd4425`，无服务端改动、远程推送或部署。

## 实现

- 原来列表 QueryState 位于工具栏上方，加载时插入段落推动输入栏。改为工具栏下固定32px反馈区域，使用小型刷新提示；同账户筛选刷新保留旧列表。
- 文本输入停顿300ms后查询；状态选择立即应用有效条件；中文输入法组合过程不提交。名称遵守服务端至少2字节限制，密钥后缀满4位才查询，中间输入只给温和提示。
- 原请求 token=abcd 被服务端 LIKE 当成精确匹配。原生适配为 token=%abcd；只接受4个ASCII字母/数字，禁止把完整Key或用户通配符发送到搜索接口。API既有查询支持此语义，不改接口。
- 请求失败提供重试，不冒充“没有匹配结果”。上一列表占位只允许站点/契约/用户/连接/代次/功能相同，避免跨账户残留。
- 顺带修正R04测试内TOML parse重载的类型标注，不改变R04业务逻辑。
