# UC-DISCUSS-BATCH-01：独立图片计划修正

用户请求“批量生成5张好看的动漫壁纸”，讨论却生成一个 `count:5` 的步骤，提示词仍包含“生成5张……每张呈现不同场景”。该提示词被逐次原样送给生图模型，造成多次输出多场景拼图。截图与现有执行路径吻合；本轮未重新调用真实模型复现。

## 范围与修复

仅修复现有跨媒体讨论的图片规划、计划预览与执行前检查。沿用 `codex/opentu-text-chat`，无新字段、协议、依赖、数据库迁移或额外规划请求。用户已有画布作品与历史讨论保留，不自动重试或重新生成。无付费调用、push、PR 或发布。

- 已配置文本模型、本地 Codex 使用相同的图片规划规则。明确区分输出文件数量与一张图中的格子/场景数量。
- 不同场景、不同提示词逐张输出 `generate_image`，每步 `count:1`；宽泛的多张壁纸请求允许规划不同场景，每条完整保留统一风格与单幅构图要求。明确用户数量优先于默认数量。
- 同一提示词的独立变体仍支持 `count>1`；明确拼图、漫画、分镜请求保留多格构图。不会用正则强拆自然语言场景，也不在执行时静默改写用户已预览的提示词。
- 保守识别句首明确的中英文“生成 N 张 / create N images”等整批命令，阻止错误计划进入预览/执行，并提示用户在讨论中重新规划。该检查不代表覆盖所有语言或所有语义歧义。
- 执行保存的旧待确认计划时，先检查全部步骤，再写提交标记与入队；错误计划不会部分提交。存储校验不增加语义拒绝，旧讨论仍可读取，已经完成的任务不重放。
- 预览显示编号和每条独立提示词；重复同一提示词的步骤明确显示“同一提示词 × N”，避免把多次变体误当成多个独立创意。
