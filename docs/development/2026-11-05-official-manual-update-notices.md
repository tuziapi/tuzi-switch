- `origin` 为正式仓库；继承的 `fork` 为历史测试远程，本任务未向其发送任何写操作。

## 问题与决定

正式 v1.5.5 采用未签名手动安装交付，旧检测入口仍只读取签名更新清单，导致缺失或陈旧清单不能正确提示正式 Release。此前已有手动安装检测模块，但尚未接入正式客户端。

正式 stable 构建直接查询本渠道 GitHub 最新公开稳定 Release，不再依赖签名清单判断是否有新版。这是用户批准的手动安装模式，不是发生验签错误后自动绕过校验；原签名安装实现、公钥、其他历史渠道逻辑均保留。以后恢复正式应用内签名安装需另行调整该路由。

- 启动后约 1 秒检查，运行期间每 6 小时检查；回到前台或恢复网络时沿用 15 分钟节流。
- 新版本显示全局提醒与更新标记；“查看更新”及设置入口先打开说明弹窗，不自动打开浏览器。
- 用户点击“下载安装包”后复核元数据，再打开对应系统的正式 Release 安装文件；支持 macOS ARM/Intel、Windows EXE 和 Linux AppImage。下载后由用户手动安装。
- 沿用版本忽略偏好。网络失败不显示“已是最新”；不退回测试仓库。
- 元数据必须为同一仓库的稳定版，四个平台安装文件均有效，地址、上传状态、非零大小及 SHA256 元数据符合要求。点击时若最新版本已变化则拒绝旧操作，需重新检查；并发点击仅触发一次下载交接。
- 更新说明按纯文本渲染；不执行其中 HTML。上述摘要检查是元数据验证，不等于客户端对浏览器下载字节进行验签或哈希复核。

## 交付限制与回退

当前公开 v1.5.5 不会因本地源码修改自动获得新提醒。需将本提交集成到后续正式版本并重新打包发布，旧用户先手动安装一次包含此改动的版本。此次未验证新原生安装包、各平台实际安装或线上新版提醒；浏览器平台模拟不等于四平台实机验收。

可用独立提交的 `git revert` 回退；不改变用户数据、应用身份、公钥或已公开附件。决策补充见 [ADR-018](decisions/0018-official-release-channel.md)。
