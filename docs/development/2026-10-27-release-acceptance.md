## 主要风险

1. **旧工具同步一致性**：`McpService::upsert_server` 先完成数据库保存，再同步旧工具配置；后续文件操作失败可能使数据库与工具文件不一致。界面失败后刷新不能修复该不一致。新增工具的补偿也不能保证进程崩溃时跨文件和数据库原子性。
2. **Pi 管理归属跨设备风险**：`pi_managed` 保存在 MCP 数据库记录并包含在 SQL/WebDAV 同步中。另一设备若存在同名、连接内容相同且已禁用的独立 Pi 配置，恢复的标记可能使其被视为受管条目，随后编辑或删除可能修改该配置；现有内容和状态检查无法证明本机所有权。需明确本机归属策略并验证跨设备冲突。
3. **导入可能部分成功**：导入过程中部分记录可先写入，后续配置错误可能使操作报错但留下已导入记录；需要明确用户反馈和恢复方式并验证异常路径。
4. **发布证据不完整**：缺少可复现的最终代码版本、当前原生包、真实桌面联调及账户/API 版本配对，无法判断本次改造可安全发布。

1. 处理上述一致性和跨设备归属问题，并补充失败注入、备份恢复和冲突回归；确认导入部分成功的交互及恢复策略。
2. 留足构建空间，基于确定的最终源码构建桌面包，在隔离环境完成真实 UI → IPC → 文件 → 三个实际 CLI 的添加、启停、导入、删除和重启验收。
3. 对账户及既有工具进行版本配对回归，在获授权的环境完成真实服务验收；覆盖安装升级、备份恢复和回退，以及目标平台安装包。
4. 固定客户端与 API 最终 SHA、契约、部署顺序和回退方案，完成用户验收及独立发布授权后，才能作出上线决定。
