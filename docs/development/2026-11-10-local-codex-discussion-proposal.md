## 核查依据

- 官方 TypeScript SDK 文档：<https://developers.openai.com/codex/sdk>

- 本机 `/Users/sdy09/.npm-global/bin/codex --version` 返回 `codex-cli 0.160.0`。只执行版本、帮助及离线协议生成，无模型请求。
- 本机生成协议确认存在模型列表、会话/轮次、停止、回复增量和思考摘要事件；宿主动态工具字段在 experimental 协议内。首版不依赖实验性动态工具。

App Server 是适合嵌入产品的结构化接口。SDK 适合 Node/TypeScript 自动化；本项目已有 Rust 原生层，直接管理 stdio 子进程可避免再打包一个 Node 运行时。具体模型、图像能力、额度依本地配置和账号实际能力核查，安装 CLI 不等于本地离线推理或免费使用。

## 可选方案

| 方案 | 优势与适用场景 | 缺点 / 维护成本 | 主要风险 |
| --- | --- | --- | --- |
| A：CLI 直接执行并输出文件 | 原意最直接，适合简单原型、单次文件生成 | 初期低，后续聊天历史、停止、产物识别需要补齐 | 终端文本解析脆弱；无法仅凭“成功”文字认定文件可导入；需约束文件操作 |
| B：App Server + 兔子现有生成队列（建议） | 持续讨论、独立模型选择；保留已有生图服务、批量确认和画布归属 | 中等；需要进程/会话桥接、协议版本检测 | CLI 升级差异、连接中断、会话与画板绑定；两处调用额度分别核算 |
| C：官方 TypeScript SDK + 本地服务 | 适合已有 Node 服务的应用，可复用事件与线程封装 | 本仓要增加运行时和跨进程服务，维护中等偏高 | 打包体积、服务生命周期及额外 IPC 故障面 |

以上是实现评估，用户随后已确认“连接用 Codex，未连接用原文本模型”，按 B 的架构落地这两个状态。

## 建议 B 的具体首版

1. 讨论区新增来源选择：`兔子文本模型 / 本地 Codex`。选择 Codex 后显示本机连接状态、可用模型与思考强度；图片/视频/音频执行模型继续在底部选择。
2. Tauri 原生层按需启动 `codex app-server --listen stdio://`。复用 CLI 自己的登录管理；前端只收脱敏连接状态，不复制登录文件或共享兔子账户令牌。不修改全局 Codex 配置。
3. 每段兔子讨论保持原画板 ID，按需把已保存上下文交给本轮独立 Codex thread。仅把用户发送的内容、选中素材及必要上下文传入；不导入其他 Codex 历史。
4. 实际回复增量、可用的思考摘要和工具状态映射到现有窄条/讨论面板。没有摘要时显示状态，不伪造推理文本。
5. 首版让 Codex 返回有结构约束的生成计划；沿用现有计划校验、固定执行模型和“预览后执行”。应用拥有模型路由与画板身份，Codex 不能覆盖它们。
6. 用户确认后沿用兔子队列。图片/视频/音频按原规则回填；文本默认留在讨论，需要时点击“放入画布”。首版最多 10 个生成任务，失败只显示已知状态，不因重连自动重复付费任务。
7. 停止当前 Codex 轮次与取消已提交媒体任务分别处理。收起讨论不停止执行；没有活动轮次时可释放子进程，按需恢复线程。增量消息合并刷新，画布不跟随每个 token 重绘。

用户例子：底部选某个图片模型 → 讨论选择本地 Codex → 输入十条海报需求 → Codex 整理可编辑/可确认的计划 → 用户点击执行 → 兔子按已选图片模型生成并在原画板排布。

## 第二阶段：Codex 本地产物

按后续明确授权增加受限输出目录与产物清单。只导入已确认的结果：检查真实路径（含符号链接）、MIME、大小、可解码性、任务及原画板身份，并记录产物指纹防止重复插入。支持的图片/视频/音频走现有资产缓存；文本经用户操作插入；HTML/代码暂作文件结果，不能直接当可执行画布内容。

是否能够让 Codex 原生生成图片，需要按该账号、CLI、模型和工具实际验证；视频和音频先复用兔子已有模型，不能由安装 CLI 推断可用。实验性宿主动态工具或 MCP 可作为后续桥接方案，首版不依赖其自动执行。

## 验收与范围

连接/退出、模型枚举、流式和停止、恢复会话、不同画板隔离、无重复提交、计划取消、媒体落位、文本手动插入以及空闲资源占用分别测试。先使用合成 App Server，再在用户批准的额度内做真实验证。

本轮已授权双路由的本地实现，不改 Codex 登录、不新增后台守护服务、不启用付费调用、不 push/PR/发布。连接按钮做可用性探测；实际轮次按需启动进程、结束即回收，历史上下文由兔子会话提供，避免空闲常驻和历史混入。初次连接失败仍使用原文本模型；已启用后发生错误则明确报错，只有用户断开才恢复原文本模型。

仓库现有 `src-tauri/src/codex_config.rs` 包含 App Server 启动/握手/配置查询，可参考但不直接复用同步阻塞调用。新流式路径使用后台阻塞线程、限量事件通道、停止信号和进程回收。首版限讨论与计划，禁用 CLI shell、插件/应用、hooks、图像内置工具及既有 MCP 服务，不让规划绕过兔子确认流程。
