# UC-PERF-02：批量三列布局、提前占位与事件隔离

2026-11-06。用户选择 B（三列 + 完整占位 + 定向性能优化），并允许适度重构。基线 `f91ebc43338765e2785f4765a31098bea4f83e28`；本地分支 `codex/batch-grid-performance`。本轮不发布、不推送，不改版本或下载脚本。

## 行为与实现

- 新批次从左到右排列，每行最多 3 张；按整批矩形避让已有内容，结果使用各自既定槽位，保留参考图关联。原有图片不重排，单张行为保留。
- 同步校验后，在参考图/路由等异步准备前建立全部轻量 SVG 占位；准备图层不创建任务、不进入画布持久化、不挂载额外 React 根。真实占位挂载后移除准备图层；准备失败、切板或卸载清理图层与内存预留。部分插入失败时，只清理没有绑定/排队任务的占位。
- 拆出 `image-batch-preparation.ts`（布局预留、绘制、清理、后台窗口绘制等待）和 `image-batch-reservations.ts`（按画板维护临时区域），主提交逻辑负责协调。避免对整个大型 AIInputBar 做无关重写。
- 固定提交时的画框选择；提交阶段按批次左上方定位一次并保留缩放，避免居中第一张把第三列推到屏幕外。批量结果自动插入不再逐张滚动视口，用户拖动后保持当前位置。
- 占位标签显示 `i/N`，旧无序号堆叠节点仍显示 `N 张`。旧横排开关替换为三列说明；保留旧存储值，不迁移用户数据。
- 图片就绪通知携带元素 ID，只刷新匹配占位；完成通知按任务 ID 匹配。控制器稳定订阅，读取最新任务/占位引用，减少重复订阅与无关历史任务扫描。

## 字段兼容与回退

唯一新增调用字段是 `CanvasInsertionParams.scrollToResult?: boolean`，缺省 true。quickInsert、insertImageGroup、insertGeneratedImageFlow 的末尾可选参数同样缺省 true；自动批量图片显式 false，普通单张和手动插入沿用原行为。无数据库、账户接口、持久配置或依赖变更，仍使用已有 batchId/batchIndex/batchTotal。旧数据和已排队任务不重排。

临时预留是 WeakMap 内存数据，清理幂等，不导出、不保存。回退可 revert 本次提交；无需数据迁移。回退后新提交回到旧布局，已经保存的结果位置保持不变。

## 性能证据与限制

复验脚本 `tests/visual/creative-batch-performance.cjs` 使用真实本地画布、工作流、队列、SVG 绘制和 IndexedDB，仅原生 HTTP 边界合成，阻断外网；浏览器配置隔离，不访问用户项目或付费模型。

计时从 Playwright 点击前开始，包含点击派发开销。启动记录的是 DOM 中完整占位集合，并不意味着 20 张同时位于屏幕内。原版合成 20 张第一次非零采样已有 20 个，没有复现“先 1 后 20”；因此不把异步准备或竖排直接认定为用户反馈的已证实根因。延迟引用准备的定向测试确认，当前全部准备占位能在异步操作未完成时出现。

| Chrome 6 倍 CPU 降速，20 张空画布 | 基线 | 修改后复验 |
| --- | ---: | ---: |
| 点击前计时至首个完整占位采样 | 229.7 ms | 114.6 ms |
| 等待/输入/拖动阶段帧间隔 P95 | 16.7 ms | 16.7 ms |
| 输入事件至下一绘制回调 P95 | 12.2 ms | 11.6 ms |
| 静止 4 秒占位整树重建 / 画布保存 | 0 / 0 | 0 / 0 |
| 集中完成阶段帧间隔 P95 | 未采集 | 33.4 ms |

这是同机单次样本，不是统计显著性结果。启动采样有冷热差异；部分早期构建/测试运行时间重叠。最终拖动模拟改为每步间隔 16 ms，原基线是连续快速派发，因此不能把微小输入/帧间隔差异解释为提升百分比。等待阶段没有明显改善，集中出图仍高于等待帧间隔；还不能承诺真实设备、大图或复杂项目完全不卡。

确定性的事件回归：同一新增测试在基线控制器/同步代码上失败（无关完成读取任务列表 1 次、无关 readiness 读取 2 次），当前均为 0 次，且没有无关 React 渲染。基线源码临时验证后已恢复当前实现。

WebKit 不支持 Long Tasks API，零计数不表示没有长任务。最初快速派发鼠标移动时一次没有实际位移；加入连续移动间隔后，10/20 张均实测位移 (88,88)，保留位移断言，未调整产品拖动逻辑。
