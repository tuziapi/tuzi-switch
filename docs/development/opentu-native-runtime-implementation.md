## 实现及选择

原预览复用了 web 入口，其原生能力标记刻意关闭。直接打开旧桌面的全局标记会调用尚未注册的存储、文件、下载等命令；本轮通过明确的 `requestManual` 宿主能力接入 HTTP，保持原 IndexedDB 项目存储，不假装已经完成旧桌面全部文件命令移植。

- 手动来源：模型发现、ProviderTransport、共享归因请求、图片查询/检查使用 Rust 原生 HTTP，支持 JSON、multipart 原始字节和流式返回；不依赖账户连接。原手动供应商存储语义保持。
- 受管来源：仍只传 bindingId、generation、动作和请求体；原生校验账户、Key 和模型协议后读取模型 Key。系统令牌不用于模型请求。绑定文件按服务实例的固定 origin 校验，修复 local-preview 本地来源无法重载的问题；renderer 不能指定来源。
- 两通道共享响应流适配。新增 `ready` 消息在原生注册后发出，处理提前取消的竞争；完成、流取消和异常清理 AbortSignal 监听。未完成的请求不会自动重放。
- 手动通道只接受 HTTP(S)，拒绝 URL 内凭证、账户引用、协议/主机伪造头；不读取账户存储，不跟随重定向，不转发上游失败响应内可能回显的秘密。上传与单次响应上限 64 MiB，128 并发登记上限，连接超时 20 秒，总超时 600 秒。
- CSP 允许本地 blob 图片/音视频、worker 与字体；保持脚本策略，不开放 eval。
- 稳定管理账户回调，避免宿主普通重绘重新初始化来源选择器。
- 独立测试 bundle ID 为 `com.tuziswitch.desktop.creative.preview`。`CC_SWITCH_TEST_HOME` 同时隔离本地预览配置与账户文件，未设置时保留原预览目录。

新增 IPC 字段明确为 `ManualRequest {requestId,url,method,headers,body}`：body 可空且为 base64 原始字节，headers 为显式请求头映射，未知字段拒绝；响应新增 `ready`，原 start/data/end 保持。没有修改系统令牌契约、API 服务端或数据库 schema。

## UC-P03.1：用户反馈二级 API Key 弹窗无样式

用户在独立桌面测试窗口发现 API Key 提示变成左下角裸文本。实际原因是 `promptForApiKey` 的命令式 overlay 默认 append 到 `document.body`，脱离 `.creative-root` 样式作用域，不是字符编码损坏。已改为优先调用方容器，其次宿主 `creative-portals`，最后保留独立应用 body 兼容；创作宿主 overlay 层级高于设置窗口，尺寸受容器约束，适配浅深色。补齐 Tab 焦点循环、Escape 关闭与原控件焦点恢复。

新增 `tests/visual/creative-key-dialog-smoke.cjs`，在 1180×800、900×650 和深色窗口验证作用域、居中、输入框实际可点击且位于设置窗之上、焦点、Tab、Escape；截图人工检查通过。只使用空/合成配置，无真实请求。结果 `/tmp/opentu-p03-key-dialog/`，日志 `/tmp/opentu-p03-key-dialog.log`。修复后重新构建桌面包，最终构建日志 `/tmp/opentu-p03-desktop-fix-build.log`。

修复后完整创作包/renderer/macOS 调试包重新构建通过，二级弹窗和配置浏览器回归再次通过；已终止本轮旧测试进程并沿用同一隔离 home 启动新包。通过 macOS Accessibility 实际打开新版创作配置和 default 分组的补填 Key 弹窗，窗口内弹窗为 432×560、位置 (744,273)，处于 1200×800 主窗范围内并水平居中；保留弹窗供用户查看。未输入真实 Key，也未发起模型调用。
