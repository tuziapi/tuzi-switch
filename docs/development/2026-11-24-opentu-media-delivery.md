## 实现与兼容

| 契约 | 新增或调整 | 默认与兼容 |
| --- | --- | --- |
| 视频创建 | `seconds?: integer`、`size?: string`、`aspectRatio?: string` | 显式参数要求确定模型来源；按本地模型能力校验，不静默改成相近值。旧调用保持默认行为 |
| 模型列表 | 视频 `capabilities`：秒数、尺寸、比例、默认值与来源说明 | 使用已选来源的有效配置；这是客户端配置能力，不是供应商效果保证。独立比例目前仅对 MiniMax-H3 和具有匹配像素尺寸的模型开放 |
| `opentu_list_tasks` | `limit` 1–50（默认10）、可选媒体类型/状态 | 仅用户可见任务，按创建时间倒序；text 映射原 chat 任务。限制文本及 URL 大小，排除路由凭证与内部任务 |
| `opentu_get_task` | `waitMs` 0–20000（默认0）、受限格式的 `remoteId`、请求参数摘要、插入状态、后续动作 | 保留常用结果字段和文本内容；不再返回完整内部 TaskResult/错误对象，错误详情在助手中查看。大 Data URL 不经过协议返回，使用结果交付 |
| `opentu_get_task_result` | `taskId`、`index`（默认0） | 只取已完成的图片/视频/音频任务，每次一个输出；返回 `outputCount`，供应商多返回时不误称重复提交 |
| 原生 `creative_export_mcp_media` | 主窗口 Raw bytes + `x-media-kind` | 不接受路径、URL、任意文件名；应用数据目录 `opentu-results`，按内容摘要复用副本，保留用户修改过的副本 |
| 交付结果 | `path`、`mimeType`、`bytes`、`outputCount`、`insertedToCanvas`，可选 MCP image 内容 | 原文件最大128MB（图片沿用64MB/3200万像素验证）；图片 JPEG 预览最长边768、最多512KiB；原文件字节不改 |
| initialize | 操作顺序 instructions | 先选模型、一次提交、保留任务号、有界续查、完成后交付；不自动重试不确定的付费提交 |

没有新增数据库字段或迁移，没有向工具配置写入模型凭证。生成默认 `insertToCanvas=false` 保持兼容。结果交付会新增本地文件，因此声明为非只读、可重复获取的工具；不上传到新服务，不打开保存窗口，不改剪贴板。退出/解除 MCP 不删除用户已生成的文件。

视频通用轮询修复：原实现声明 `maxAttempts` 却无限循环；现在执行默认1080次上限，超时返回 `VIDEO_POLL_TIMEOUT` 并保留远端编号。超时不是供应商取消或生成失败证明，也不允许自动重新提交。其他恢复执行器已有独立轮询上限，不混淆其行为。

## 设计取舍

沿用工具调用和现有生成队列，避免依赖每次打开模型菜单；需要 UI 时仍使用实际可见控件。结果保存本机并返回预览，比新增公网托管服务少一项账户、存储与隐私依赖，但远程客户端无法读取本机视频。客户端必须支持本机媒体或展示工具图片内容。不能保证所有 ChatGPT 客户端内嵌播放。

未增加付费请求自动重试或声称幂等生成；原协议没有端到端幂等事务，丢失创建响应必须先查最近任务。读取任务、插入成功、对话展示分别验收。
