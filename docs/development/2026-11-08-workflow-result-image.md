## 原因与实现

完整编译页面使用真实队列、画布、IndexedDB、Cache Storage，仅原生 HTTP 返回合成棋盘图片。修复前任务完成、画布显示正常，但助手结果 `<img>` 直接使用 `/__aitu_cache__/image/content-….png`，`complete=true`、`naturalWidth=0`。这是内部缓存标识，桌面端没有 Web Service Worker 将其作为普通图片路径提供。

- 图片结果复用既有 `RetryImage` 和统一缓存读取，优先使用本地 Blob，继续支持普通网址和内联图片。缓存读取失败时可使用已有缩略图；单独的缩略图不可用时尝试结果原图。
- 静态“正在加载图片”提示；有界加载和重试结束后显示“图片暂时无法显示 / 重新加载图片”。重载仅重新读取现有结果，不调用工作流重试，不创建生图任务，不改变历史任务完成状态。
- 图片加载成功后单击或键盘激活打开现有完整预览。按钮键盘事件与画布快捷键隔离。
- 复用现有 Blob 生命周期清理，丢弃卸载后的迟到读取，无轮询或持续占位动画；父级普通刷新不重复读取图片缓存。

无新增依赖、数据库字段、配置、账户权限、接口契约或数据迁移。既有视频/音频结果显示路径不变。修复不保证已丢失的源文件可恢复，不自动重生成图片；模型调用成功率不属于本次显示故障验证。
